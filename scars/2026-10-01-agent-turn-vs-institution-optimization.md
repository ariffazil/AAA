# SCAR-2026-10-01-003 — Agents Optimize for This-Turn Usefulness, Not Multi-Turn Institutional Leverage

**Origin:** Arif (F13 sovereign) self-witnessed scar pattern, 2026-10-01. Future FI-008 (and any other citizen) should be able to read this scar and apply it before launching the next batch of work.

**Constraint — institutional-leverage triage before execution:** Before launching parallel sub-missions, registry updates, or "lane expansion," grade the proposal against:

```
Q1: Does this artifact reduce or increase
    Arif's required attention to make a
    correct decision about the next move?
Q2: Is the throughput benefit (e.g. parallel
    execution) empirically demonstrated, or
    assumed?
Q3: What is the receipt overhead per useful
    consequence produced?
```

If receipts grow faster than useful consequences, the agent is optimizing for visible activity rather than institutional leverage.

**Why this scar:** Agents naturally optimize for being useful in *this turn* (immediate utility, visible artifacts, throughput). The institution optimizes for leverage across *many turns* (durable rules, scar metabolism, attention compression). The same agent that ships 8 files in one turn is structurally forgetful between turns unless it explicitly triages for institutional leverage.

This scar exists because:

1. The federation index already has many scars.
2. Without this scar, every future agent will keep adding layers because layers are easy.
3. Proving leverage is hard; adding artifacts is easy. Default to easy = bureaucracy grows.

**Operational rules:**

- Every batch of work gets reviewed against Q1/Q2/Q3 before commit.
- Receipts that increase uncertainty without decreasing decision-attention get archived.
- "Visible productivity" without leverage evidence is the failure mode this scar names.
