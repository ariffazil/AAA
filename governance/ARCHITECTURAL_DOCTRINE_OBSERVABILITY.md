## The Five Laws of Observability

### Law 1: LIVE PROBE or UNKNOWN

Every system state claim MUST come from a live probe. If the probe fails → state is UNKNOWN, not "healthy", not "safe", not "0.99".

**Violation:** Hardcoded status strings in MOTD scripts, dashboard generators, or agent outputs.
**Example violation:** `FQ: 0.99 (Healthy)` when no `:7073/health` probe was run.
**Fix:** Every display script MUST curl the live endpoint. If curl fails → print `UNKNOWN`.

### Law 2: No Propaganda Layer

A display that always says "safe" regardless of reality is worse than no display. It trains the human to ignore warnings.

**Violation:** `SOVEREIGN STATUS: System safe & operational` when no probe was run.
**Fix:** Display MUST reflect probe result. If no probe → display nothing or display `UNVERIFIED`.

### Law 3: The Session Briefing (What Just Happened)

Every agent spawn MUST know:
- What changed since last session (git log, VAULT999 tail)
- What was completed (carry_forward.completed_this_session)
- What's next (carry_forward.carry_forward)
- What's blocked (carry_forward.open_loops_888_HOLD)
- What the metabolic state is (FQ from live probe)

**Tool:** `/root/scripts/governance/generate-session-briefing.sh`
**When:** Agent session start, after `arif_init`
**Why:** `carry_forward.json` answers "what's next" but not "what just happened."

### Law 4: The State Pipeline (SOT → State → Renderer)

```
Live probes (curl :PORT/health)
    ↓
Machine-readable state (/var/run/arifos_state.json)
    ↓
Human-readable display (now, 06-arif-live, session briefing)
```

**Rule:** Never generate the display from anything other than the state file or live probe.
**Rule:** The state file is a cache (TTL 5 min), not a source. Live probe is always SOT.

### Law 5: One Display Per Purpose

| Purpose | Tool | Status |
|---------|------|--------|
| Temporal anchor + federation state | `now` | ✅ Live, probed |
| Login MOTD | `06-arif-live` | ✅ Live, probed |
| Session handoff | `generate-session-briefing.sh` | ✅ Built |
| Agent dashboard | `/var/run/arifos_state.json` | ✅ Generated by cron |
| Hardcoded propaganda | `05-arifos` | ❌ KILLED |

**Anti-pattern:** Building a new display tool when one already exists.
**Rule:** Before building ANY display, check if `now`, `06-arif-live`, or the session briefing already covers it.
