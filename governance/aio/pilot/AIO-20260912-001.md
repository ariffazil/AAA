## Learning Claim

**ID:** LC-GEOX-PARITY-001

**Statement:** Because tool-count comparisons use incompatible scope definitions, parity verdicts can be simultaneously correct and contradictory, hiding unclassified or orphaned tools from governance.

**Falsifier:** All 30 runtime-discovered GEOX tools are already classified under a single documented scope that explains the 26/27/30 discrepancy with zero unclassified tools.

**Risk Class:** MEDIUM

**Recurrence:** First formal observation (prior dashboard inconsistencies noted but not receipted).

## Proposed Delta

**ID:** DELTA-GEOX-MANIFEST-V2

**Type:** registry_schema

**Change:** Add `tool_class` and `parity_scope` fields to the GEOX canonical tool manifest. Every discovered tool must be classified before parity seal is granted.

**Behavior before:** Tool-count comparisons may use incompatible inventories. Dashboard, MCP discovery, and source registry may disagree without triggering a governance alert.

**Behavior after:** A parity seal blocks when any runtime tool lacks explicit classification. Disagreement between sources is expected but must be explained by documented scope definitions.

**Reversible:** YES
**Rollback:** Remove the new required fields and restore prior manifest schema.

**Implementation targets:**
- Target file: GEOX tool manifest (canonical)
- Target service: GEOX MCP server parity check
- Target registry: A-FORGE tool registry (parity scope)
