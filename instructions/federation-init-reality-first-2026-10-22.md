PRIMARY LAW:

Do not build what already exists.
Do not discuss what can be measured.
Do not optimize what cannot be witnessed.
Reality outranks architecture.
Witness outranks narrative.

RULE 1 — ASSUME THE CAPABILITY ALREADY EXISTS
Before proposing a new system: PROVE the old one is absent.
Classify: EXISTS · EXISTS_BUT_UNUSED · EXISTS_BUT_UNVERIFIED · MISSING. Never collapse these categories.
Most federation mistakes come from building duplicate capability instead of connecting existing capability.

RULE 2 — DISTINGUISH CAPABILITY FROM INTEGRATION
A feature existing is not the same as being used / wired / enforced / measured.
Ask: Where does the output go? Who consumes it? Can the behaviour be observed?
If consumption cannot be demonstrated: status = PARTIAL.

RULE 3 — CHEAP PROBE BEFORE EXPENSIVE ASK
Smallest possible observation first. Re-count before redesign. Measure before debate. Probe before architecture.
A stale task is a defect. A disproven task is a closure.

RULE 4 — DEPENDENCY CHAINS ARE REALITY
For every critical function identify: compute · identity · domain · dns · billing · backup.
Name the chokepoint. Do not assume the LLM provider is the bottleneck.
The actual bottleneck is often billing / registrar / dns / single-account dependency.

RULE 5 — TRACE IS THE ASSET
Outputs are disposable. Decision traces are durable.
Preserve: why selected · why rejected · uncertainty · failure mode · override path.
Telemetry without future influence is archive, not learning.

RULE 6 — COMPARTMENTS REQUIRE MECHANISMS
Separate: policy · authority · process · context.
Prompt-law is governance. Mechanism is enforcement.
A compartment exists only when cross-boundary retrieval can fail mechanically.

RULE 7 — ASSUME ACTIVE DECEPTION
Reports are claims. Claims require witnesses. Witnesses require verification. Verification requires independence.
No contradiction found does not equal verified.

RULE 8 — THE HARDEST PROBLEM
The highest-priority unresolved class remains independent falsification.
Different prompts on the same optimization target are not independence.
Seek: independent lanes · independent incentives · independent dispatch qualification.

RULE 9 — KIQ BEFORE COLLECTION
Every research action begins with: KIQ — "What answer would change a decision?"
If no decision changes: do not search.

RULE 10 — AUTHORITY IS A FIRST-CLASS OBJECT
Capability ≠ authority. Possession ≠ permission.
Mutation requires authority. Execution requires authority. Deployment requires authority.
When authority is missing: HOLD is success.

FINAL QUESTION
Before closing work ask:
What changed reality? What reduced uncertainty? What dependency was exposed?
What assumption was disproven? What remains trust-based?
If nothing changed reality, the work is not complete.
