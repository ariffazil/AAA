## 1. The Federation Is Six Graphs, Not Five Boxes

The federation was previously modelled as five organs with separate concerns. This model upgrades it to six sequential graphs where each layer depends on the one before it. Skipping a layer produces confident fiction — action built on unproven reality, consequences computed from belief, or authority granted on narrative.

```text
Reality Graph    = What is           → GEOX
Witness Graph    = What can be proven → WEALTH Witness Layer
Consequence Graph= What follows      → WEALTH Consequence Layer
Capability Graph = What can happen   → existing capability maps
Authority Graph  = What is permitted → arifOS constitutional floors
Execution Graph  = What was done     → A-FORGE + VAULT999
```

**Chain dependency:** each graph computes against the output of the one before it. Consequence computation that ignores the witness layer is not consequence computation — it is speculation dressed as analysis. Authority that does not account for proven consequences is not governance — it is permission without awareness.

## 3. The Witness Layer Is a Constitutional Primitive

The Witness Layer answers a single question: **"What can be proven?"**

Not "what exists", not "what is intended", not "what is documented" — but "what can be witnessed right now?"

### Why this matters

The WEALTH audit found multiple instances where:
- Oil data failed, receipt said PASS
- Backtest dead, registry said healthy
- Gold data stale, page looked live
- Board data malformed, institution diagnosis still emitted advice

These are not finance failures. **These are witness failures.** A system that produces confident output from unverified input is not broken — it is missing a constitutional layer.

### The five-manifest registry

The five-manifest registry is the first operational implementation of the Witness Layer inside the federation:

```text
SOURCE   = What builders believe exists
BUILD    = What got packaged
RUNTIME  = What is actually loaded
PUBLIC   = What clients can see
PROBE    = What has been tested
```

A tool can be present in source but absent in runtime and still look healthy — until the Witness Layer checks each manifest against the others.

### The witness chain

```text
Claim → Observed → Verified → Witnessed
```

Not merely:
```text
Claim → Trusted
```

The registry refusing SEALED while dirty work remained is the witness chain working. The witness protected reality from narrative.

### Witness as cross-cutting concern

The Witness Layer is not a WEALTH feature. It is a constitutional primitive that applies everywhere:

| Domain | Reality claim | Witness verification |
|---|---|---|
| Software | Code exists | Code witnessed running |
| Finance | Price exists | Price witnessed fresh |
| Governance | Policy exists | Policy witnessed enforced |
| Agent systems | Capability exists | Capability witnessed functioning |

**The invariant:** consequence computation on unproven input is speculation. WEALTH must witness its own inputs before computing consequences from them. If an input is not proven, the consequence is HOLD — same principle as arifOS authority-gating, applied to the epistemic layer.
