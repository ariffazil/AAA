## The Four Bloat Types (solution hierarchy — dedup files alone is not enough)

```text
1. PhysicalBloat  — duplicate files          (mesh already solves: 1 tree, symlinks)
2. SemanticBloat  — two artifacts, one idea  (collapse into one owner)
3. SurfaceBloat   — too many discoverable names (WELL 40/10; 8 search providers)
4. AttentionBloat — too much resident at once (the most dangerous)
```

## Three-Temperature Model

```text
HOT   (always resident, ≤ few k tokens):
      Identity + Safety + EpistemicInvariants + Routing

WARM  (cheap discoverable metadata — always visible as pointers only):
      CapabilityName + OneLinePurpose + Trigger + IO + Authority

COLD  (heavy knowledge — case studies, doctrine, examples, matrices):
      retrieve only when triggered

Attention exposure = HOT + Relevant(WARM) + TinySubset(COLD)
```

## Migration Law (HERMES: filesystem intelligence → capability substrate)

```text
Preserve invariants. Externalize doctrine. Expose capabilities.
Retrieve detail. Execute validators. Do NOT preload knowledge.
Never: 525 files → 525 MCP tools (that moves entropy, schema bloat).

```
