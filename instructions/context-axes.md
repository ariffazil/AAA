# Context Geometry — Orthogonal Axes (Forged 2026-09-02)

> Context is not files. Context is an orthogonal vector space.
> Every context surface owns EXACTLY ONE axis. Overlap = blob. Orthogonal = geometry.

## The routing rule

Before writing ANY durable fact, ask which axis it belongs to:

- Who Arif is / who I am → IDENTITY (SOUL / user memory)
- A rule, floor, tier, gate → LAW (constitution/autonomy/zen)
- An event, scar, decision, person-detail → MEMORY (memory tool / H-doctrine)
- A machine fact, endpoint, path, convention → PROTOCOL (base/pointers/skill)
- Live system condition → STATE (probe, never persisted as fact)
- Anything that dies with the turn → INTENT (never write it down)

**Iron rule:** one fact, one owner, one axis. If the same fact can be true
from two files, one of them is a pointer or it is deleted. Delete contradiction
faster than you create context.

## Decay

When an entry drifts into a second axis, do not copy — move it, and leave a
pointer behind. Pointer lines are cheap; duplicated truth is civilization debt.
