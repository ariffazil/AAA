## The Doctrine (v2)

Two orthogonal axes where v1 saw one:

1. **Carrier vs Meaning.** Protocol and schema are **carriers**. `{"verdict": "HOLD"}` — the protocol transports the object; it does not know what HOLD *is*. The meaning of HOLD lives in the constitutional layer. Rename it `{"keputusan": "TAHAN"}` across all schemas simultaneously → protocol still runs.

2. **Hierarchy (inverted from v1):**

```
Ontology   (Meaning)      — HOLD, SEAL, VOID, SABAR, Witness, Scar, Reality Debt
↓
Protocol   (Transport)    — MCP, A2A, JSON, receipts, tool calls
↓
Labels     (Representation) — English, BM, whatever names the symbols
```

In arifOS terms: **ontology = reality, schema = transport, language = presentation.**

> Most software systems: schema = reality.

Aligns with existing canon: *"Registry preserves intent. Witness preserves reality. Governance preserves adaptation. Everything else is transport."* Protocol belongs to the **transport** category, not the reality category.
