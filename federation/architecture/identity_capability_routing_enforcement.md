## The principle

The federation separates four concerns, each living in its own canonical location:

| Layer | Question | Location | Cardinal rule |
|---|---|---|---|
| **Identity** | What is the role? | Agent cards (`.md`/`.json`), AAA registry | Identity is by role, runtime-agnostic |
| **Capability** | What can be called? | MCP servers (`mcp.json`, `mcp-launchers/`, `mcp__*__*`) | Capability surface is harness-agnostic |
| **Routing** | Which model to ask? | FED (`federation-models.json`, `fed_route`) | Routing is constitutional, not cost-driven |
| **Enforcement** | Whether to allow? | `judge-gate.ts`, constitutional hooks | Enforcement is programmatic, not model-dependent |

Four locations. Single source of truth per concern. References between layers, never duplication.

## Why this matters

When concerns collapse into one location, drift is inevitable. Single-location SOT is the only architecture that survives:

- **Harness swap** (Kimi Code ↔ OpenCode ↔ Hermes): identity stays in cards, capability moves to new MCP surface
- **Model change** (M3 ↔ K3 ↔ DeepSeek): capability surface stays, routing layer swaps models
- **Constitutional change** (F1–F13): enforcement stays, identity/capability adjust to new floors

## The convergence evidence

Three harnesses — OpenCode, Kimi Code, Hermes — written independently, all converge on the same shape: **one primary, many subagents, no nesting**. Flat call tree. Single F13 sovereign veto point. This is not coincidence; it's rediscovery of the same architectural principle:

- "No nesting" prevents circular dispatch (topological impossibility)
- One primary = one F13 veto point = clean sovereign intervention
- Subagents see only their delegated context (information containment)

Harness-level invariant today. Whether it should become a federation contract is an open question — emergent convention has worked so far.

## The 4-layer diagnostic table

When something breaks, the symptom maps to a layer:

| Symptom | Diagnosis | Layer | Resolution |
|---|---|---|---|
| Tool exists but permission denied | Capability wired, identity gate missing | Capability → Identity | Add permission rule (F11 gate) |
| Card exists but agent unreachable | Identity declared, capability link stale | Identity → Capability | Wire to MCP or archive identity |
| Model selected but floor blocks | Routing misaligned with enforcement | Routing → Enforcement | Step 2 spec via observation |
| Reversible action blocked | Identity ceiling too low | Identity | Re-register with correct ceiling |
| Agent loops infinitely | Nesting violation | Topology | Constitutional contract? |

## Open questions for federation doctrine
