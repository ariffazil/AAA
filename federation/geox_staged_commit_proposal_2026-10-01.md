## 1. Atomic commit strategy — three options, one recommended

### A. Single commit (Lane 333d's working tree as-is)

8 mods + 2 new files in one commit. Pros: matches the receiver's mental model exactly; the repair is one logical unit; reviewer signs off on the whole story in one pass. Cons: the new CI gate lands **bundled with the changes it is supposed to gate** — a reviewer cannot tell whether `surface-drift-gate.yml` is *self-consistent* (would catch drift on its own) without first applying Step 2's pack change and the regenerated artifacts that make it green. A broken gate would only be discovered *because* the source change happened, which inverts the order of proof.

### B. Two commits (hand-authored vs generated)

Commit 1: source + workflow + test (6 files — `generate_all_surfaces.py`, `registry.py`, `geox_middleware.py`, `tools_manifest.yaml`, the new CI workflow, the new test). Commit 2: the 4 regenerated artifacts (`contracts/tools.yaml`, `tools.json`, `tools_sot.yaml`, `CANONICAL_PUBLIC_SURFACE.json`) produced by `python3 scripts/generate_all_surfaces.py`. Pros: separates "what humans decide" from "what machines derive" — the principle the generator itself states: "registry.py is the ONLY truth. Every surface is GENERATED from it." Cons: between commit 1 and commit 2, `main` is **structurally red** — the new gate would fire and report the artifacts as drifted. CI sees a broken tree for one push. A human merge window could be confused.

### C. Three commits (recommended) — gate first, source second, refresh third

Commit 1 (gate): workflow YAML + the 18-test derivation suite + the `--check` mode added to `scripts/generate_all_surfaces.py`. **No source-of-truth change.** The gate is exercised against the *current* truth (26 public tools, `public_count_target: 31` already wrong) and **expected to fail on `tools_sot.yaml`, `CANONICAL_PUBLIC_SURFACE.json`, `tools.json`, `contracts/tools.yaml`** because timestamps and one truth drift already exist. Reviewer sees: gate works → existing drift is *what the gate is for*.

Commit 2 (source): `registry.py` (`derive_recovery_tool`, `recovery_is_callable`, `_is_non_mutating`), `geox_middleware.py` (RT1 derives recovery from the registry), `tools_manifest.yaml` (pin `geox_surface_status` into `earth_core`). **No generated refresh yet.** After commit 2, the gate is expected to flag new drift (a real tool-addition drift, plus the still-present 31-vs-26 mismatch).

Commit 3 (refresh): `contracts/tools.yaml`, `tools.json`, `tools_sot.yaml`, `src/geox_mcp/generated/CANONICAL_PUBLIC_SURFACE.json` — regenerated by the now-landed `--check`-mode-aware generator. After commit 3, the tree is green; the gate fires green on every push until someone re-introduces drift.

**Why C beats B**: commit 1 is **independent** — the gate can be reviewed without any source change being present. Reviewer questions like "does `--check` actually compare bytes?" or "does errexit+errexit+pipefail mask anything?" can be tested against a tree where the only change is the gate itself. The first commit also surfaces the **pre-existing** `tools_sot.yaml`/`CANONICAL_PUBLIC_SURFACE.json`/`tools.json`/`contracts/tools.yaml` drift as red, which is exactly what the gate is for and turns the repair into a *fix* of something already broken, not a *claim* of perfection.

**Why C beats A**: A bundles gate + truth change + refresh in one commit. An external auditor reading commit `abc123` cannot reconstruct which lines made the gate go red vs which made it green. C preserves the order of proof: gate first (additive), then source (additive), then refresh (corrective). Each commit's `git log -p` reads like a narrative.

**Why not split the test off the gate in commit 1**: the test `tests/test_rt1_recovery_derivation.py` references `derive_recovery_tool` from `registry.py`, which does not yet exist on commit 1's tree. **Correction:** in Option C, **commit 1 carries the new test ONLY if the test can run without the new derivation API**. The cleanest path: ship the 18 derivation tests in **commit 2** alongside the derivation API. Commit 1 ships just the workflow YAML + the `--check` mode + a tiny smoke test that the gate itself exits 0 against the current tree (a guard for "the gate does not crash on a clean tree"). That keeps commit 1 truly additive and self-consistent.
