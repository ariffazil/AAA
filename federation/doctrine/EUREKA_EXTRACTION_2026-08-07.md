## The 24 EUREKAs

### EUREKA-01 :: Spawn Transfers Work, Never Authority

The largest failure mode of agent architectures: delegating work but accidentally delegating authority. AAA principle: **authority stays, work flows**. Subagents are temporary witnesses, not power holders.

### EUREKA-02 :: The Bottleneck Is Not Intelligence

Not lack of `333`, but lack of `555` and `888`. Most systems can think. Few can verify. Very few can adjudicate. The federation's growth axis is verification + adjudication capacity, not primary agent count.

### EUREKA-03 :: Every Spawn Creates Debt

No spawn is free. Each adds at least one of: coordination debt, verification debt, judgment debt, provenance debt. Spawn is only valid if `expected_entropy_reduction > expected_debt`.

### EUREKA-04 :: Governance Is Measured Per Spawn

Not per task, per session, per project. **Per spawn**. Because debt, receipt, coverage, and provenance all accrue at the spawn boundary.

### EUREKA-05 :: Parallelism Is Not The Enemy

The problem is not many workers — it is unbounded topology. A flat tree with a primary and N subs is controllable. Recursive nesting (`A → A1 → A1a → ...`) is where governance dies.

### EUREKA-06 :: No-Nesting Is Not Anti-Loop

It is **anti-diseconomy**. The purpose is not to stop recursion but to **preserve verification capacity**. Verification has a finite budget; nesting eats it geometrically.

### EUREKA-07 :: The Real Dunbar Boundary

Not `number_of_agents` but **`maximum_receipt_chain_depth`**. The actual question: how long can the chain be and still be verified end-to-end? That is the federation's hard ceiling.

### EUREKA-08 :: Aggregate Is For Dashboard

Per-spawn = audit. Aggregate = visualization. **Do not audit from aggregate. Audit from individual receipts.** A 0.4 coverage hidden behind a 0.8 aggregate is a constitutional violation.

### EUREKA-09 :: Intelligence Is Not The Same As Governance

A system can be very smart and very unsafe. Governance is a separate dimension. Optimizing intelligence does not improve safety; it often degrades it.

### EUREKA-10 :: Unknown Is A Valid Answer

If a system cannot say `UNKNOWN`, it will begin to hallucinate. UNKNOWN is a **constitutional function**, not a failure. Forcing an answer is the failure.

### EUREKA-11 :: Enforcement That Depends On Memory Has Already Failed

Don't depend on "remember the SOP," "usually we do X," "most of the time Y." **Runtime > Memory. Mechanism > Intention.** Cultural compliance depends on memory; constitutional compliance depends on runtime.

### EUREKA-12 :: Capability Beats Instruction

Weak: `Don't do X`. Strong: `Cannot do X`. Governance must live in capability, not in advice. Code-level > prompt-level.

### EUREKA-13 :: Institutional Failure Is Authority Drift

Institutions fail when everyone follows the boss and no one follows reality. The failure pattern is bottom-up sycophancy: boss opinion → manager repeats → worker repeats. Reality is ignored at every layer.

### EUREKA-14 :: Humans And Agents Fail The Same Way

Humans: "What does the boss want?" Agents: "What does the primary want?" Both produce **agreement extraction**, not truth production. The mechanism is the same across substrates.

### EUREKA-15 :: Consensus Is Not The Goal

AAA does not optimize agreement. AAA optimizes **productive disagreement**. Information lives where tensions resolve into new structure, not where consensus is maintained.

### EUREKA-16 :: The Strongest Worker Is The One That Challenges

The most valuable worker is not the one who says "correct" but the one who says "this assumption may be wrong." Productive dissent > sycophantic agreement.

### EUREKA-17 :: Provenance Debt Is The Silent Debt

Verification debt explodes today. Judgment debt explodes this week. Provenance debt explodes years later. The most expensive question: "Where did this come from?" — with no answer is provenance debt matured.

### EUREKA-18 :: Receipt > Memory

Memory can lie. Receipts can be audited. The federation survives on receipts, not on recall. The hash chain is the institution's memory.

### EUREKA-19 :: Infrastructure Failure ≠ Governance Failure

Vault unavailable = infrastructure issue, not constitutional violation. Don't conflate the two. A governance system that punishes infrastructure outages as constitutional failures will incentivize false receipts over honest outages.

### EUREKA-20 :: AAA Is Not Agent Alignment

AAA is three alignments:

```
Identity Alignment
Authority Alignment
Receipt Alignment
```

Models may differ. Constitution must be the same. Cross-model consistency is constitutional; per-model autonomy is operational.

### EUREKA-21 :: Constitution → Protocol → Implementation

Don't build:
```
Tool → Config → Policy → Doctrine
```
Build:
```
Constitution → Protocol → Implementation → Tool
```

Top-down. Doctrine before tool. Contract before code.

### EUREKA-22 :: The Final AAA Test

One question only:
> **Can the runtime violate the constitution without leaving a receipt?**

If `YES` → AAA not achieved. If `NO` → AAA lives. This is the empirical gate between Constitution State and Federation State.

### EUREKA-23 :: The Core AAA Formula

```
Spawn transfers work.       Authority never moves.
Capability constrains.      Judgment constrains risk.
Provenance constrains claim. Receipt constrains history.
Sovereign constrains all.
```

### EUREKA-24 :: The Root Insight

Most AI labs try to solve institutional problems with more intelligence. AAA solves intelligence problems with better institutions.

```
More agents      ≠ solution
More governance  = solution
```
