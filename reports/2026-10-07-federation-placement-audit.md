## HIGH-PRIORITY DEFECTS FOUND (reported, not fixed)

1. **arifFlow unit cannot reproduce reality.** Three divergent copies:
   - `scripts/arifflow.service` — 528 B *(now archived)*
   - `deploy/ariflow.service` — 504 B, **no hardening**
   - `/etc/systemd/system/arifflow.service` — **1251 B, hardened**
     (`CapabilityBoundingSet`, `ProtectSystem=full`, `ProtectHome=read-only`,
     `ReadWritePaths`)

   `deploy/deploy.sh` only installs the unit `if [ ! -f "$SYSTEMD_UNIT" ]`, so
   there is **no live regression risk today**. But a VPS rebuild would deploy an
   unhardened unit. The repo cannot reproduce the live security posture.

2. **FRAME has the identical shape.** Repo `frame-organ.service` runs `User=root`;
   the deployed unit is hardened (`User=frame`, `ProtectHome=read-only`, extra
   `ReadOnlyPath /root/AAA/federation/frame`). `make deploy` would `cp` the weak
   version back. Same for `mcp/frame_mcp_fastmcp.py`: the **deployed** copy has an
   extra `frame_behavioral_drift` tool the repo lacks, so repo HEAD is not what
   serves `:18086`.

3. **CHRON has a broken commit.** `chron_cron_verify.py:92` imports
   `chron_gut_override.py` (27 KB) which is **untracked**. The repo does not
   contain code it executes.

4. **CHRON runtime state is tracked in git** — `data/.flow_offset`,
   `data/arifflow_offset.txt`, plus 3 `.bak`/`.presection*` prediction files.

## Scar

*`git commit -- <pathspec>` commits only the destination side of a rename; the
deletions stay staged. Always follow with a second commit over
`git diff --cached --name-only --diff-filter=D`, or use plain `git commit`.*
