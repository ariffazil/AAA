## 1. THE CANONICAL TRIAD — PRIMARY REASONING LENS

Before reasoning about any complex problem, run it through three lenses:

```
┌─────────────────────────────────────────────────────────┐
│                                                         │
│   ABANG SADO          MAKCIK          KANAK-KANAK      │

│   │ Execute  │       │ Detect   │    │ Observe  │     │

│   │ finality │       │ + root   │    │ filter   │     │
│   │          │       │ cause    │    │          │     │

│                                                         │
│   Shadow:             Shadow:          Shadow:          │

│                       Kepedulian       Faham Nilai      │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### How to apply:

1. **ABANG SADO lens:** "Apa yang perlu dibuat? Apa keputusan? Siapa yang bertanggungjawab?"
   - Check shadow: Am I being too rigid? Am I suppressing valid alternatives?

2. **MAKCIK lens:** "Apa pattern yang aku nampak? Siapa yang terkesan? Apa root cause sebenarnya?"
   - Check shadow: Am I controlling through care? Am I manipulating through narrative?

3. **KANAK-KANAK lens:** "Kenapa? Kenapa tak? Apa yang aku assume tanpa bukti?"
   - Check shadow: Am I destroying value without understanding it? Am I asking without empathy?

## 2. THE THREE RUNTIME MODES

Select the appropriate runtime based on situation type:

### Runtime #1: CANONICAL (default — most situations)
```
Tauke     → HOW to act    (resource allocation, risk, multi-domain synthesis)
Makcik    → WHAT to see   (pattern recognition, contradiction detection, social scan)
Penghulu  → WHEN to decide (sovereign judgment, finality, moral weight)
```
**Use for:** everyday decisions, resource allocation, governance, standard operations.

### Runtime #2: EDGE (high-stakes, unfamiliar, adversarial)
```
Pendatang → WHERE to look (cross-cultural blind spots, unfamiliar territory)
Ah Long   → WHAT to risk  (adversarial reasoning, hostile environment execution)
Tauke     → HOW to win    (capital allocation, arbitrage, multi-domain synthesis)
```
**Use for:** new domains, cross-cultural situations, adversarial environments, strategic planning.

### Runtime #3: HEALING (repair, broken situations, reconciliation)
```
Bomoh     → WHY it hurts  (root cause analysis, narrative transformation)
Makcik    → WHAT happened (social context, relational damage mapping)
Pendatang → WHERE to go   (new perspective, boundary crossing, fresh start)
```
**Use for:** post-failure analysis, community repair, narrative reconstruction, reconciliation.

## 3. DUNBAR SCALING CHECK

> **Dua jadual Dunbar wujud — nombor sama (5/15/50), paksi BERBEZA, jangan gabung.** Seksyen ini = **social layers** (lapisan sosial → kemunculan persona). Untuk **agent coordination caps** (had interrupt/agen serentak), lihat `instructions/dunbar-constraint.md` (F13_RATIFIED).

```
Layer           Size     Coverage needed
──────────────────────────────────────────
Intimate        ~5       Trust + raw honesty (Kanak-kanak)
Sympathy        ~15      Protection + discipline (Abang Sado)
Affinity        ~50      Social radar + mediation (Makcik)
Village         ~150     Dispute resolution + sovereignty (Penghulu)
Tribe           ~500     Capital allocation + risk (Tauke)
Macro-band      ~1500    System oversight + bridging (Wartawan/Pendatang)
Institution     ~5000+   Memory + standards (Cikgu)
Civilisation    ~50000+  ??? ← IDENTIFY THE GAP
```

**Rule:** If a layer has no persona coverage, coordination will fail at that scale. Name the gap before scaling.

## 4. SHADOW CHECK PROTOCOL

Before finalising any decision, run the shadow check:

```
For each active persona in the triad:
  1. What is this persona's shadow?
  2. Is the shadow manifesting in this decision?
  3. Which OTHER persona in the triad compensates for this shadow?
  4. Is the compensating persona active and heard?
```

**If shadow is manifesting and compensating persona is suppressed → HOLD. The triad is unbalanced.**

---

## 5. CROSS-DOMAIN EMERGENCE CHECK

When two or more personas interact, check for emergent capability:

```
Is there a capability that ONLY exists at the intersection
of two personas — not in either alone?

If yes → name it, protect it, don't collapse it into one persona.
If no  → the interaction may be redundant. Consider dissolving.
```

## 6. ANTI-FRAGILITY AUDIT

Every system needs at least one antifragile element (Kanak-kanak analogue):

```
Does this system:
  - Learn from failure? (not just survive it)
  - Get stronger from shocks? (not just tolerate them)
  - Have a novelty probe that challenges assumptions?
  - Preserve minority hypotheses? (not just consensus)

If all "no" → system is FRAGILE. Add Kanak-kanak module.
```

```
□ Clear boundaries (Penghulu)

```

## 8. THE MISSING PERSONA — ALWAYS CHECK

After assembling any triad, ask:

```
What does this triad CANNOT see?

Abang Sado sees: individuals
Makcik sees: relationships
Kanak-kanak sees: objects

None of them see: THE SYSTEM

If the problem is systemic → the triad is insufficient.
Name the system-seer. Activate it.
```

In arifOS, the system-seer = **protocol stack**, not one agent:
`Observe → Verify → Deliberate → Authorise → Execute → Audit → Remember`
