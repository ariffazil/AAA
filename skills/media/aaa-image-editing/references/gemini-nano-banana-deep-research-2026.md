# Gemini Nano Banana Deep Research (2026-08-13)

Condensed from Google dev blog, Vertex AI docs, aitoolsguidebook.com, and
gemilab.net production pipeline analysis. Session source: Hermes Agent
deep research on image editing best practices.

## Model Family — Full Specs

### gemini-2.5-flash-image (Nano Banana, legacy)
- **Release:** October 2025 (GA)
- **Retirement:** October 2, 2026
- **Resolution:** up to 2K (1024px longest side default)
- **Token cost:** 1290 tokens per image (flat across all aspect ratios)
- **Aspect ratios:** 1:1, 2:3, 3:2, 3:4, 4:3, 4:5, 5:4, 9:16, 16:9, 21:9
- **Input limit:** 65,536 tokens
- **Output limit:** 32,768 tokens
- **Max images per prompt:** 3
- **Max file size (inline):** 7 MB
- **Max file size (GCS):** 30 MB
- **SynthID:** Watermarked by default
- **Knowledge cutoff:** June 2025
- **Google recommendation:** "We strongly recommend transition to Nano Banana 2 Lite"

### gemini-3.1-flash-image (Nano Banana 2)
- **Role:** Most versatile generalist workhorse
- **Strength:** State-of-the-art 4K generation, world knowledge, reliable text rendering
- **Multi-reference:** Up to 10 objects + 4 characters
- **Status:** GA

### gemini-3.1-flash-lite-image (Nano Banana 2 Lite)
- **Role:** Fastest, cheapest — velocity and scale
- **Limitation:** Not optimized for multiple reference inputs or multi-turn editing

### gemini-3-pro-image (Nano Banana Pro)
- **Role:** Premium — most complex visual tasks
- **Strengths:** Highest world knowledge, advanced localization, brand consistency,
  Google Search grounding, default "Thinking" process for composition refinement
- **Multi-reference:** Up to 14 objects + 5 characters
- **Text rendering:** Best in family — single-line error rate <10%
- **Pricing:** ~$0.039 (1K) / ~$0.134 (2K) / ~$0.24 (4K)

## Critical API Behavior — Reference Image Ignored

Production triage order (from gemilab.net field report) for when the model
silently ignores your reference image and returns a different picture:

1. **`response_modalities` missing IMAGE?** (~80% of "only text returned")
   - `["IMAGE"]` alone or `["IMAGE", "TEXT"]` together are both fine
   - `["TEXT"]` alone → no image output, just description
2. **Parts order** — image part FIRST, text SECOND. Flipping order causes model
   to treat text as primary request and image as loose style reference.
3. **MIME type must match actual bytes** — JPEG labeled as `image/png` → silent drop
4. **Image size** — sweet spot 1024–1568px longest side. Over 4K → "thumbnail-grade"
   output. Under 128px → treated as no image attached.
5. **Prompt conflates "generate" and "edit"** — ambiguous prompts drift toward
   generation mode. Use explicit "Using the provided image as the base" anchor.
6. **Chat sessions drop reference after turn 2** — older image parts squeezed by
   token compression. Solution: re-attach latest output as fresh input each call.

## Multi-Turn Editing — Known API Instability

From Google AI Developers Forum (2026-06-25 to 2026-07-05):

- **404 NOT_FOUND** on turn 2+ chat replay (state resolution broken)
- **400 "Image part is missing a thought_signature"** — spurious validation error
  on correctly-signed payloads, usually cleared by identical retry
- `gemini-3.1-flash-image` hit hardest: ~90% conversation failure for 9 days
- Failure rates swing 0%→~100% within hours with no client change
- Single-turn generation unaffected throughout

**Conclusion:** Stateless single-turn calls are the only reliable pattern for
image editing in production pipelines as of 2026-08-13.

## Official Prompt Patterns (Google Dev Blog)

### Image Editing — Adding/Removing Elements
```
Using the provided image of [subject], please [add/remove/modify]
[element] to/from the scene. Ensure the change is [description of
how the change should integrate].
```

### Semantic Inpainting — Editing Specific Area
```
Using the provided image, change only the [specific element] to
[new element/description]. Keep everything else in the image
exactly the same, preserving the original style, lighting, and
composition.
```

### Character Consistency Pipeline (from Signals/aktagon.com)

For preserving a character across multiple scenes:

1. Start with archive image → create character reference sheet
   (front view, back view, white background)
2. Each scene generation: include character sheet as Image 1,
   previous scene as Image 2
3. Reference sources explicitly in prompt: "Image 1: Character sheet.
   Image 2: Previous scene. The robot from image 1 stands..."
4. State continuity: "The robot no longer holds the map" (explicit removal)
5. Save intermediates at every step — no reliable rollback in chat

### Iterative Refinement
```
Turn 1: "Make the lighting warmer"
Turn 2: "Keep everything the same, but change the expression to serious"
```

## SynthID Watermark

All images generated by ALL Nano Banana models include an invisible SynthID
digital watermark. This is non-disabling, non-removable (as of 2026-08-13).

## Imagen Deprecation

Imagen models deprecated — shutdown date August 17, 2026.
Google recommends migrating all image generation to Nano Banana models.
