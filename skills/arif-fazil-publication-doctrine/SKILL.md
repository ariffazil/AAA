# arif-fazil-publication-doctrine

The 3-register framework governs what leaves the federation and what stays. F13 SOVEREIGN directive (Arif, 2026-08-11): **publish the question, hold the vulnerability, audit closure criteria**. The doctrine's job is to prevent two failure modes — publication-as-attractor collapse (premature disclosure of defensive gaps) and performative humility (F9 violation when structure-less gap-talk signals virtue without changing anything).

## The 3-register framework

```
Register A — Public Doctrine       Register B — Research Frontier       Register C — Internal Audit
─────────────────────────          ─────────────────────────────       ───────────────────────────
Stable canon                      Public, structured questions         Private, never web
F1-F13 floors                     Question + Evidence-of-Gap           Specific vulnerabilities
Separation of powers              + Would-Become-True                  Calibration error rates
Governance-first                  + Why It Matters                     Attack paths
Reality-before-narrative          + Current Status                     Implementation gaps
Human sovereignty                 Auditable, falsifiable,              Exploit feasibility
                                 action-oriented
Surface: /constitution/,          Surface: /research/frontier/*        Surface: /root/AAA/audits/,
/doctrine/, /000/                 (one keystone page first,            /root/forge_work/,
                                  replicate if pattern earns)          /root/secrets/INDEX.md
```

**Register rules:**
- **A → B → C** is the strict ordering. A page goes to B (research question) before the gap is closed, then to A (doctrine) only when mature, NEVER to C (private).
- **C → B is forbidden.** Internal vulnerabilities cannot be promoted to public questions. The question is "How would an honest federation learn X?" — never "We have a vulnerability in X, here's the question".
- **B → A is gated on closure criterion.** A research-frontier page promotes to doctrine only when the Would-Become-True criterion passes audit.

## Register B — Research-frontier page structure (5 parts)

Every Register B page MUST carry these 5 sections. No more, no less. Anything more is marketing. Anything less is performative.

```
1. QUESTION
   One sentence. The paradox or gap, framed as research question.
   "How can constitutional systems learn without self-authorizing constitutional mutations?"

2. EVIDENCE OF GAP
   Concrete reference to missing code/doc/primitive.
   "/root/arifOS/GENESIS/ contains F1-F13 floors stable since 2026-07.
    No machine doctrine exists for non-sovereign-initiated evolution.
    E20 truth metabolism re-verifies truth claims, not constitutional claims."

3. WOULD-BECOME-TRUE CRITERION
   Testable closure condition. Future agents must be able to falsify this.
   "Gap closes when a proposed amendment:
    - originates from observed contradiction (reality-driven)
    - passes 888 triple-pass audit
    - is ratified by F13 (sovereign remains the gate)
    - leaves auditable trail (F11 preserved)
    - does not enable self-modifying law"

4. WHY IT MATTERS
   1-2 sentences. Stakes, not philosophy.
   "Without this, constitutions become museums. F13 is a single point
    of failure across the federation."

5. CURRENT STATUS
   Date + latest action + next concrete step.
   "2026-08-11: proposed, awaiting F13 ratification as keystone.
    Next: forge the amendment-proposal primitive in arifOS kernel."
```

**Falsifiability rule (F2 binding):** if a researcher can't write a fix and check it against the Would-Become-True criterion, the page is performative, not auditable. Restructure or remove.

## Publication-as-attractor discipline

Publishing a gap creates THREE simultaneous attractors:
1. **Collaborators** — researchers who want to help close it
2. **Attackers** — agents who now know your surface
3. **Competitors** — who may publish faster to claim the gap

**Resolution: publish the QUESTION, not the VULNERABILITY.** Same gap, different register.

| Publish this (B — research question) | Not this (C — internal vulnerability) |
|---|---|
| "How can constitutional systems learn without self-authorizing constitutional mutations?" | "Our F1-F13 stability depends entirely on F13 sovereign intervention; no machine doctrine exists for non-sovereign-initiated evolution." |
| "How does a federation calibrate confidence bands by claim class?" | "Current confidence values are heuristic. No Brier-score ledger per claim category. Strategic predictions ~2x over-confident." |
| "How can an agent detect when a metric is being Goodharted?" | "Our organ metrics have no anti-Goodhart layer. An attacker who knows our success metrics could optimize for them while degrading actual outcomes." |

F6 dual-register already covers this at the kernel level (MARUAH internal, EMPATHY public). Apply it on the adversarial layer specifically.

## Performative humility risk (F9)

"What arifOS Is Actively Trying To Learn" is NOT "What arifOS Still Does Not Know". The first becomes a research program. The second becomes marketing. Test:

```
Does the page move the gap toward closure?           YES → research program
                                                      NO  → performative signal
Does the page have an audit-able closure criterion?  YES → research program
                                                      NO  → performative signal
Would a researcher be able to falsify a proposed fix? YES → research program
                                                      NO  → performative signal
```

## AI-jargon-leakage detection (Register A voice rule)

Public doctrine surfaces must NOT carry federation-internal jargon. Specific offenders and replacements:

| Forbidden on public surfaces | Replace with |
|---|---|
| "F13 is final" | "The human veto exists because some decisions should never be automated." |
| "Hard floors VOID. Soft floors HOLD." | "Thirteen rules. Each one earned. Each one breakable by sovereign choice." |
| "888 JUDGE (MIND)" | "The judge" or "the constitutional court" |
| "A2A gateway" | describe the function (e.g., "lets agents find and call each other") |
| "physics-gated geoscience" | describe the constraint (e.g., "every claim must be tied to a measurement") |
| "capital thermodynamics" | describe the discipline |
| "vitality reflection" | describe the practice |
| "constitutional intelligence kernel" | describe what it does |

**Probe before claiming zen:** search the public surface for these terms. `grep -i "F[0-9]\{2\}\|VOI[D]\|HOLD\|SEAL\|888\|constitutional intelligence" /root/arif-fazil.com/sites/arif-fazil.com/dist/<path>/` — any hit on a public doctrine surface is a leak. Fix the META title first (highest-leverage), then body.

**Where jargon DOES belong:** `llms-full.txt` (the machine-facing dump), `canon/*.json` (the machine canon), internal `/000/` archive if marked MIND ring, `/999/` proof chamber. The split rule:

```
llms.txt       — human-readable. What is arif-fazil, what is arifOS, where to go.
llms-full.txt  — full jargon. Canonical SOT for LLM training ingestion.
```

If you can't tell which file a term belongs in, ask: would a stranger with no federation context understand the term on first read? NO → `llms-full.txt`. YES → `llms.txt`.

## Pitfalls

### Orphan stubs rot trust

`/organs/` is a meta-redirect card with no real content: `<meta http-equiv="refresh" content="0;url=/doctrine">`. Either build it properly OR kill it with 301. Never leave a half-built redirect as decoration — it tells the reader the federation doesn't finish what it starts.

### Empty surface directories are louder than no directory

`/essays/` contains 7 PNG essay-content images but no rendered essay pages. To a stranger this looks worse than no `/essays/` at all — proof that the content exists but wasn't finished. Either render the essays from the PNGs, OR quarantine the PNGs to `/forge_work/essays-pending-render/` and 301 `/essays/` to `/words/writing/` or `/world/`.

### META title/description is the highest-leverage single line

The `<title>` and `<meta name="description">` are what strangers see in search results, social shares, and the browser tab. Even if the page body is clean, a jargon META poisons the first impression. Fix META before body.

### Don't mix A and C in the same file

`llms.txt` (Register A) and `canon/*.json` (Register C) MUST be separate files. If you find yourself writing "F13 SOVEREIGN" in `llms.txt`, you have C content in an A file. Move it to `llms-full.txt` or `canon/`.
