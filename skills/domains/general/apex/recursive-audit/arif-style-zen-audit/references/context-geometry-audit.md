# Context Geometry Audit — orthogonal axes over context files

Forged 2026-09-02. Diagnosis shape: "drift risiko bukan fail hilang, tapi
semantic overlap" — every context surface speaking about the same thing from
a different angle, so intelligence becomes a blob instead of geometry.

## The six axes (the target state)

| Axis | Question | Owner (SOT) |
|---|---|---|
| IDENTITY | Who am I? | SOUL.md + memory `user` store |
| LAW | What is allowed? | constitution.md + autonomy.md + zen.md |
| MEMORY | What happened? | memory tool + human-memory.md + VAULT999 |
| INTENT | What is being asked now? | live session — never persisted |
| STATE | What is the system right now? | `now` + carry_forward + probes — never persisted as fact |
| PROTOCOL | How do I operate the box? | base.md + pointers.md + skills |

The axis map lives canonically at `/root/AAA/instructions/context-axes.md`
(ref-wired into AGENTS.md and CLAUDE.md via render-agents.sh). If it moved,
find it: `grep -l 'Context Geometry' /root/AAA/instructions/*.md`.

## Recipe (proven sequence)

1. **Read every surface that enters the prompt** — /root/AGENTS.md,
   /root/CLAUDE.md, /root/.hermes/SOUL.md, instruction fragments, memory
   stores. Never trust the drift report's file list; verify yourself.
2. **Find concrete duplicates** — same fact asserted in two files (e.g. a
   "session start checklist" in both zen.md and base.md). Quote both before
   calling it a finding.
3. **Kill the duplicate, leave a pointer** — the canonical owner keeps the
   fact; the other file becomes a one-line pointer naming the owner.
4. **Forge a fragment if an axis has no owner** — e.g. nothing named the
   axis boundaries → new `context-axes.md` fragment.
5. **Wire new fragment into the composer** — edit
   `/root/scripts/render-agents.sh`, add `ref:<fragment>` to BOTH the
   AGENTS.md and CLAUDE.md render_one blocks (they are separate lists;
   missing one means the axis only reaches half the surfaces).
6. **Re-render**: `bash /root/scripts/render-agents.sh` — expect
   "AGENTS.md: rendered" + "CLAUDE.md: rendered".
7. **Verify**: `head -8 /root/AGENTS.md` shows the new fragment in the
   header list; `wc -c` confirms size stayed sane.
8. **Apply the axes to the agent's own memory** — check memory notes for
   facts that duplicate the USER profile (identity axis). Consolidate in ONE
   batched memory call: replace the duplicate entry with a slim ops-intel
   version + pointer.

## Pitfalls

- Rendered files carry a `GENERATED by render-agents.sh` header — editing
  them directly is dead work, next render overwrites.
- render-agents.sh fragments >6000 bytes get wrapped in `<details>` — keep
  new fragments small so they stay inline.
- Two skills named alike across dirs (`capabilities/audit/...` vs
  `.archive-...`) will make skill_view ambiguous — pass the categorized path.
- Memory consolidation = single batched call, not two sequential ones
  (budget is checked on final state only).
