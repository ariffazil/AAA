# Dual-lane UA routing — pitfalls (2026-09-17)

`/world/makcikgpt/*` is served in **two lanes chosen by User-Agent**, and the two lanes
give different bytes for the same URL. Any probe that ignores this reports the wrong
thing — including your own browser tests.

## The lanes

| Lane | Trigger | Root | try_files order |
|---|---|---|---|
| bot/crawler | UA matches `GPTBot\|ClaudeBot\|PerplexityBot\|…\|TelegramBot\|HeadlessChrome\|curl\|wget` | `/var/www/html/arif/makcikgpt-md` | `{path}` then `{path}.md` then `{path}.html` then `{path}/index.html` then `/index.html` |
| human | anything else | `/var/www/html/arif` | `{path}` `{path}/index.html` `/world/makcikgpt/index.html` `/index.html` |

Caddy handler + regexes: `/etc/caddy/vhosts/arif-fazil.com.conf`, the `@mk_article_bot`
and `handle /world/makcikgpt/*` blocks.

## Pitfall 1 — a new article without a static mirror 200s the LISTING

The bot lane's terminal fallback is `/index.html` inside `makcikgpt-md/`, which is the
**listing page**. So a slug with no `makcikgpt-md/<slug>.md` and no `<slug>.html` returns
**HTTP 200 serving the listing** — not a 404. Share the link on Telegram and the preview
card is the listing; a crawler indexes the wrong page; the author sees "it works" because
his own browser (human lane) renders the article fine.

**Both lanes must be probed on publish:**

```bash
SLUG=my-new-article
# human lane — must return the SPA shell that references /assets/index-
curl -s -o /dev/null -w '%{http_code} %{size_download}\n' \
  -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/124.0 Safari/537.36" \
  "https://arif-fazil.com/world/makcikgpt/$SLUG"
# bot lane — must return the ARTICLE, not the listing (check for a body marker)
curl -s -A "TelegramBot" "https://arif-fazil.com/world/makcikgpt/$SLUG" | grep -c '<a marker from the article>'
```

A 200 is not evidence of correct content in either lane. Grep for a string that exists in
the article and not in the listing.

Mirrors are generated by `scripts/generate-md-mirrors.cjs` into
`public/makcikgpt-md/` and synced to the webroot — if the file is absent, the generator
did not run for that entry (check the article is in `src/data/makcikgpt/index.ts` and
`ecses.json`), rather than "the route is broken".

## Pitfall 2 — your headless browser is a BOT

`HeadlessChrome` is in the bot regex. A `browser_exec`/Puppeteer/Playwright probe
**lands in the bot lane**, so it sees markdown or the listing while a real user sees the
React article. Do not conclude "the page is broken" from a headless render.

To test the human lane from a headless context, override the UA **before** navigation:

```python
cdp('Network.setUserAgentOverride',
    userAgent="Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/124.0.0.0 Safari/537.36",
    platform="Win32")
goto_url(url)
```

`Emulation.setUserAgentOverride` did not take effect in one session; `Network.` did.
Verify with `js('navigator.userAgent')` before trusting the render — if it still says
Headless, you are still in the bot lane.

## Pitfall 3 — social previews are generic by design gap, not by bug

The bot lane serves `.md` (raw markdown, no `<head>`, no `og:` tags). The per-slug SPA
shell carries **site-level** og tags (`og:title` = site title, `og:url` = root), not the
article's. Net effect: pasting any MakcikGPT link yields a generic card.

Fixing it is public-facing (Caddy lane change and/or per-slug og injection in
`scripts/copy-static-html.js`) → deploy gate applies, get the go signal first. Two options:

1. Drop `TelegramBot`/`Twitterbot`/`facebookexternalhit` from the bot regex so preview
   fetchers receive the SPA shell (which at least has og tags today), or
2. Prefer `{path}.html` before `{path}.md` for preview bots, and inject per-article
   `og:title`/`og:description`/`og:image` into the mirror in `generate-md-mirrors.cjs`.

Option 2 is the durable one — the preview should describe the article, and it keeps the
md-first lane intact for AI crawlers.

## Rule of thumb

When the same URL serves different bytes by client, **name the client with every claim**.
"The article 200s" is not a finding; "bot lane returns the listing, human lane returns the
article" is.
