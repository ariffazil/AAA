## When to Use

Use this skill when Arif (F13) is acting as **intermediary** between
Hermes and a third party who needs procedural/administrative guidance
in Bahasa Melayu (or English-BM code-switch). Typical triggers:

- Arif relays a friend's/family member's situation with brief context
- Arif asks for a PDF, voice note, or written brief to forward
- Arif says "Masalah manusia" or "kawan aku" — indicating real person
  in distress, not a hypothetical
- The third party needs to NAVIGATE a process (withdraw, claim, register,
  apply, appeal) — not make a life decision

**Do NOT use this skill for:**
- Emotional/life decisions where the third party needs space to think
  (use `decision-advisory`)
- Arif's own affairs (use direct task execution)
- Hypothetical or research queries with no real recipient

# Third-Party Advisory Documents — Arif as Intermediary

When Arif is helping someone ELSE navigate a procedural/administrative
situation (withdrawal, claim, registration, application, appeal), this
skill governs HOW to produce the deliverable.

The recipient is a REAL HUMAN in difficulty. Maruah (F6) requires the
output to be dignified, useful, and honest. F2 requires we never
fabricate specific figures, fees, deadlines, or current rates when we
have not verified them.

This is NOT a class for emotional life-decision coaching (see
`decision-advisory` for that). This is procedural help for a third party,
with Arif as intermediary.

## Core Principles

### 1. THE RECIPIENT IS A REAL PERSON

Ayu in this session = a real friend of Arif in cashflow distress. The
PDF/voice note that arrives in her Telegram or WhatsApp is judged by her
perception of Arif's helpfulness, not yours.

Quality bar:
- **Dignified** — never condescending, never lecture-y, never "financial
  advisor" voice
- **Direct** — short sentences, active voice, BM Penang kalau Arif's
  tone
- **Honest about limits** — label what needs verification at the
  counter / online system, never pretend certainty on live-changing facts

### 2. MINIMUM CONTEXT BEFORE PRODUCTION

Arif often delivers context in 3-4 lines ("Che Rohayu ni kawan aku.
Dia nak withdraw akaun 3. Cashflow issue. Masalah manusia"). DO NOT
ask 10 clarifying questions. Ask the ESSENTIAL 3-5:

1. **Who is the recipient to Arif** (kawan / family / stranger) —
   affects tone & signoff
2. **The actual procedural question** (what specifically — which
   account, which form, which office)
3. **Why now** (cashflow / medical / deadline / opportunity) —
   affects urgency framing & whether alternatives matter
4. **Output format** (PDF / voice note / text only / bilingual)
5. **Anything we MUST NOT say** (Arif may have personal context — e.g.
   don't suggest PTPTN if religious reasons, don't mention insurance
   if she has none, etc.)

If Arif doesn't answer all 5, ASK ONLY the missing ones. Don't ask
what you can infer.

### 3. F2 HONESTY ABOUT VERIFICATION GAPS

This session exposed a real pattern: when web_search returns empty,
Cloudflare blocks kwsp.gov.my, and SearXNG can't extract — **DO NOT
fabricate specific numbers, current rates, exact i-Akaun UI steps, or
fee schedules**. Instead:

- State clearly: "Ni dari memory aku. Benda yang berubah-ubah (kadar
  dividen, UI i-Akaun, fee) kena double-check kat kaunter atau portal."
- Label what is robust (procedure rules, eligibility logic, account
  structure) vs what is volatile (current rates, latest UI, policy
  micro-changes)
- NEVER invent specific figures to look helpful

**Pitfall:** It's tempting to fill gaps with plausible numbers. The
recipient trusts Arif's name on the document. A wrong fee figure = real
financial harm.

### 4. ARIF IS THE INTERMEDIARY, NOT THE AGENT

Ayu should NOT feel she's been handed off to an AI. The voice/tone
should be Arif's voice (or close enough that she reads it as Arif's
care), not Hermes's.

Practice:
- Sign off as Arif, not as Hermes (unless Arif says otherwise)
- Match Arif's tone: BM Penang casual, short, direct
- If Arif gave a phrase ("Masalah manusia"), preserve it in framing
- Do NOT add disclaimers that break the intimate voice ("Disclaimer:
  this is generated by an AI...")

### 5. PDF vs VOICE NOTE vs TEXT — FORMAT TRIAGE

| Recipient / Context | Best format | Why |
|---|---|---|
| Mobile-only, stressed, no reading time | Voice note (≤60s) | Hear it while doing other things |
| Need to keep record / reference later | PDF + text | Has to be re-readable |
| Procedural with many steps | PDF (numbered steps) | Bookmarkable |
| Emotional, decision-time | Voice note | Heart, not paper |
| Quick "kat mana" / "berapa lama" | Text only | No noise |

When in doubt, ask Arif: "PDF ke voice note? Kalau voice note, nak
Penang BM ke standard?"

Voice note rules (inherits from `decision-advisory` §4):
- Keep ≤60s for personal delivery
- Speak in same register as conversation
- Ground with simple closing statement
- Edge TTS Malay is borderline acceptable for INTERNAL brief but NOT for
  real-world to real people — check `tts.provider` config first; warn
  Arif if MiniMax/OpenAI/ElevenLabs not available

### 6. STRUCTURE FOR PROCEDURAL DOCUMENTS

When the deliverable is procedural (steps, forms, requirements), use:

```
# [Topic in 1 line — BM]

[Dignified 1-2 sentence opener that acknowledges the human situation,
not just the procedure]

## Sebelum Mula
[Pre-conditions: who's eligible, what to prepare, what to bring/know]

## Step-by-Step
[Numbered, 1 line each, action verb first]

## Hal Penting / Pitfalls
[What most people miss — fees, timing, documents commonly rejected,
what triggers delays]

## Double-check Bila
[Specific things to verify LIVE at counter / portal because memory
may not match current state]

## Tanda Arif Prihatin
[Optional 1-2 lines from Arif, not from Hermes]
```

For withdrawal / financial decisions, add:
- Real cost (dividend foregone vs interest saved)
- Whether the math makes sense (brief, 2 lines)

### 7. VERIFICATION GAP LABELING (MANDATORY WHEN LIVE PROBE FAILS)

When you couldn't confirm facts live (Cloudflare block, search empty,
SearXNG extract failure), the document MUST say so. Honest format:

```
⚠️ Sila verify kat [kaunter/i-Akaun/portal]:
   - [item 1: e.g. current dividen rate Q4 2026]
   - [item 2: e.g. minimum withdrawal amount]
   - [item 3: e.g. processing time terkini]
```

This is NOT weakness — it's F2 in action. Arif gets to say "I had
someone help me draft this, but verify the live bits yourself." That
protects Ayu's trust in Arif.

### 8. THE "MASALAH MANUSIA" FILTER

Before producing the document, ask: "Adakah dokumen ni nampak macam dia
tak berbaloi jadi manusia, atau macam kawan yang ambil berat?"

Test cases that FAIL this filter:
- Lecturing tone ("Anda harus sedar bahawa...")
- Over-formal headers ("PROSEDUR PENDAFTARAN PENARIKAN...")
- Bullet-only with no warmth
- Ending without grounding

Test cases that PASS:
- Casual opener that acknowledges the situation
- Steps that feel like a friend explaining
- Closing line that reminds her she's not alone in this

## Common Malaysian Procedural Context (Verify Before Stating)

These are the categories of third-party advisory tasks Arif gets:
- EPF/KWSP withdrawal (Akaun Fleksibel, Akaun 2, Akaun 1, specific
  purposes like housing, medical, education)
- ASB/ASB2 unit redemption
- PTPTN settlement / discount applications
- Credit card debt restructuring / AKPK
- SOCSO / EIS claims
- Income tax filing (e-Filing, e-Borang)
- Insurance claims (motor, medical, life)
- Hospital bills dispute / subsidy application
- Court fine / summons settlement
- JPJ license renewal, road tax
- Immigration / passport renewal
- School registration / exam appeals
- Utility bills dispute (TNB, Air Selangor, Unifi)

For each of these, MEMORY-BASED KNOWLEDGE is the baseline. LIVE
VERIFICATION is required for:
- Current rates / fees / charges
- Latest UI steps in online portals
- Recent policy micro-changes (last 6 months)
- Active promotions / discounts / moratorium periods

### EPF Akaun Fleksibel — Reference State (verify before publishing)

Note: this is MEMORY-BASED, not live-verified. KWSP reforms of 2024
restructured accounts into Akaun 1 (Pencen), Akaun 2 (Sejahtera),
Akaun 3 (Fleksibel). For Akaun 3 withdrawal:

- Eligibility: any member with balance in Akaun Fleksibel
- Withdrawal: anytime, no purpose restriction
- Minimum withdrawal: RM50 (typical, verify live)
- Method: i-Akaun (web/app) or counter
- Dividend: still credited to remaining balance
- Tax: not taxable for member withdrawal (verify)
- Processing: typically 7-14 working days online

These specifics MUST be labelled as "memory-based" in the document.

## Pitfalls

- **Never fabricate specific figures.** If you don't have the current
  rate, say so. This is the same lesson as `decision-advisory` §1.
- **Never drop Arif's voice.** The document goes out under Arif's name.
  Don't make it sound like an AI generated it.
- **Don't lecture.** A friend in cashflow distress doesn't need a
  financial literacy course. She needs the steps.
- **Don't add disclaimers that break intimacy.** "Disclaimer: I'm not
  a licensed financial advisor" belongs at the END as one line, not
  upfront.
- **Don't over-format.** A 12-page PDF for "withdraw EPF" is overkill.
  One page, structured, scannable.
- **Don't skip the verification label.** Recipient must know what to
  re-check live.
- **Don't push alternatives Arif didn't sanction.** If Ayu wants to
  withdraw, that's her call. Don't lecture about "better alternatives"
  unless Arif asks for that analysis.

## Workflow

```
1. Arif gives brief context (3-5 lines usually)
2. Identify the class: emotional decision vs procedural guidance
   → If procedural → this skill
   → If emotional/life-decision → decision-advisory
3. Ask ONLY the missing 3-5 essential clarifying questions
4. State verification gaps honestly BEFORE drafting (so Arif knows
   what will be labelled "memory-based" vs "live-confirmed")
5. Produce draft in chosen format (PDF / voice / text)
6. Self-test against "Masalah manusia" filter — would Ayu feel cared
   for, or processed?
7. Deliver to Arif with one-line summary: what it is, what to verify
   live, what to sign off as
```
