# MakcikGPT static surface — routing, source layout, generator

Session-verified 2026-08-07 while rebuilding all 22 `/makcikgpt-md/<slug>.html` pages.

## Caddy routing (what actually serves what)

From `/etc/caddy/Caddyfile` (~lines 800–870, 2026-08):

- `redir /world/makcikgpt /world/makcikgpt/ 308`; `@mk_slug` regex `^/makcikgpt/(.+)$` → 301 to `/world/makcikgpt/{slug}`; `@mk_trail` strips trailing slash `/world/makcikgpt/<slug>/` → 301.
- `@ai-bot-landing` (UA regex: GPTBot|ClaudeBot|PerplexityBot|OAI-SearchBot|anthropic-ai|Google-Extended|Bytespider|Amazonbot|ChatGPT|curl|python-requests|node-fetch|Go-http-client) + path `/world/makcikgpt/` → `root * /var/www/html/arif/makcikgpt-md`, `try_files /index.html`.
- `handle /world/makcikgpt/` (browser landing) → rewrite to `/index.html` from `/var/www/html/arif` (SPA shell).
- `@ai-bot-world` (same UA regex, path `/world/makcikgpt/*`) → `uri strip_prefix /world/makcikgpt`, `root * /var/www/html/arif/makcikgpt-md`, `try_files {path} {path}.html {path}/index.html /index.html`.
- `@makcikgpt_nojs` (`path_regexp ^/world/makcikgpt/(.+)$`, NOT Accept: text/html) → strip prefix, `try_files {path}.html {path}.md =404`.
- `handle /world/makcikgpt/*` (browser articles) → SPA shell `/index.html`.

So: **static `<slug>.html` files live in `/var/www/html/arif/makcikgpt-md/`, NOT under `world/`.** The dir also holds `<slug>.md` bot payloads and `index.html` (regenerated by `scripts/generate-makcik-index.cjs` from `essays.json`).

## Source of truth

- Article body: `/root/arif-fazil.com/sites/arif-fazil.com/src/data/makcikgpt/<slug>.ts` → `html: \`...\`` template-literal field. 22 articles; all but `iran-hormuz.ts` begin with `<div class="cover">…</div>`.
- Metadata: `makcikArticlesMeta` array in `src/data/makcikgpt/index.ts` (title, subtitle, date, domain, language, excerpt, tags, seal, claim_register/source_ledger for sealed pieces). `essays.json` does NOT carry subtitle/abstract — only id/title/date/lang/series/tags/dest/seal.
- Slug list / canonical order: `essays.json` entries where `lang==='bm'` and `dest.path` starts `/world/makcikgpt/` (see `scripts/lib/makcik-source.cjs`).

## Generator

`scripts/generate-makcik-articles.cjs` (site root, run: `node scripts/generate-makcik-articles.cjs`) writes `public/makcikgpt-md/<slug>.html`. Deploy:

```bash
cp public/makcikgpt-md/*.html /var/www/html/arif/makcikgpt-md/
chown www-data:www-data /var/www/html/arif/makcikgpt-md/*.html
chmod 644 /var/www/html/arif/makcikgpt-md/*.html
```

### Gotchas hit while building it (all fixed in the script)

1. **Slug extraction:** `dest.path` is `/world/makcikgpt/<slug>` with NO leading slash issue from `path.join` — must strip with `replace(/^\/world\/makcikgpt\//, '')`, not string replace of `/world/makcikgpt/` (which leaves the leading slash → `path.join` resolves it to site root → "file not found").
2. **SITE_ROOT:** hardcode `"/root/arif-fazil.com/sites/arif-fazil.com"` — `path.resolve(__dirname, "..", "..")` is fragile when the script is invoked via `node -e` or from a different cwd.
3. **JS shadowing:** naming a local `const readMin = readMin(articleBody)` shadows the function → `ReferenceError: Cannot access 'readMin' before initialization`. Rename the local.
4. **Cover strip must be depth-tracked:** `<div class="cover">` contains a nested `<div class="cover-byline">`; `/<div class="cover">[\s\S]*?<\/div>/` stops at the INNER close → leaves orphan `</div>` in the body. Walk div open/close tags counting depth; on depth 0, slice.
5. **After cover strip, also strip:** orphan `<hr />`, duplicate `<h1>`/`<h2>` title repeat, and `<p><strong>…999 Meterai | Versi x.x…</strong></p>` byline repeats (some articles, e.g. `dap-8-tahun-bangang`, `searah-senyum-media-suap`, repeat title+subtitle+byline after the cover). Known residual: the `<p><strong>subtitle</strong></p>` dup line in `searah-senyum-media-suap` needed a broader strip rule — check first body paragraph of generated pages for dup bylines before declaring done.
6. `iran-hormuz.ts` has no cover — starts directly with `<h1>` + blockquote; the strip loop must be a no-op for it (it is, because `openRe` doesn't match).
7. `.ts` template literals: unescape `\"`, `\\` after regex extraction; emoji in content is fine (UTF-8).

## Bot/browser false-positive trap (session-verified 2026-08-09)

**Root cause:** Caddy's first-match-wins. The `@ai-bot-world` named matcher checks User-Agent against `curl|python-requests|node-fetch|Go-http-client|GPTBot|...`. Any tool whose UA matches that regex hits the static-file handler in `makcikgpt-md/`. Real browsers (`Accept: text/html`, Chrome/FF UA) miss that matcher and land on `handle /world/makcikgpt/*` → SPA shell → React tries to resolve the slug client-side → if slug not in the SPA bundle, renders "ARTICLE NOT FOUND".

### Why curl-based gates are unreliable on this surface

The `@ai-bot-world` regex literally includes `curl`. Any agent using curl (or web_extract, or web_search curl-based fetchers) will get a 200 + full HTML body from the static file, regardless of SPA registration. This makes curl a **bot witness only**, not a human-accessibility witness. A four-witness verification protocol is needed:

```
W1: curl -sfL (bot path)       → HTTP 200 + size
W2: grep slug in SPA bundle    → >0 (browser path)
W3: grep slug in landing page  → >0 (discovery path)
W4: browser_navigate (human)   → <h1> title, NOT "ARTICLE NOT FOUND"
```

W1 alone is insufficient. A publish reported "Gate 1–7 ALL PASSED" using curl-only gates and was wrong — human browsers saw "ARTICLE NOT FOUND".

### Two-file divergence (also found 2026-08-09)

Both files existed:
- `/var/www/html/arif/makcikgpt-md/syaitan-ingat-dirinya-malaikat.html` (12609 bytes)
- `/var/www/html/arif/world/makcikgpt/syaitan-ingat-dirinya-malaikat/index.html` (12341 bytes)

They differ: additional CSS rules in `makcikgpt-md/` (list/blockquote/strong/em/h2 styles), HTML entity encoding (`&mdash;` vs UTF-8 `—`), and a wording discrepancy (`makin kurus` vs `makin kurang` in one sentence). Always write to ONE canonical copy and `cp` to the other — never write both independently.

### Trailing-slash 301

`/world/makcikgpt/<slug>/` → Caddy `@mk_trail` → 301 to `/world/makcikgpt/<slug>` (no trailing slash). curl without `-L` returns 0 bytes + 301. Always use `curl -sfL` when probing these paths.

### File permissions note

`write_file` creates files owned by `root:root` mode 600. Because Caddy runs as root on this host (`ps aux` → `root /usr/bin/caddy run`), the 600 files are servable. This means permission errors do NOT surface — the failure mode is silent (browser gets SPA shell instead of the static file). Do not rely on permission errors to catch publish failures. Always run W1–W4 above.

## Design drift recovery — when static HTML diverges from SPA component (session-verified 2026-08-11 on `syaitan-ingat-dirinya-malaikat`)

**Symptom:** Article served via `makcikgpt-md/<slug>.html` shows the "writing-article pattern" (single-line kicker `MAKCIKGPT × PETRONAS × AMANAH · SEALED 999`, plain white h1, `By Arif Fazil` byline pill). User shows a reference screenshot with richer design (two-line kicker `Civilization Intelligence · Ξ WEALTH ·` + `MAKCIKGPT × PETRONAS × AMANAH`, italic red h1, `Bahasa Makcik` pill, orange subtitle) and says "design lari".

**Root cause (this pattern):** Three converging drifts:

1. **Lost `.ts` source.** The file `src/data/makcikgpt/<slug>.ts` was removed from the working tree at some point. SPA bundle no longer has the slug registered, so SPA can't render.
2. **Static HTML written with simpler fallback pattern.** Whoever wrote the static HTML used the "writing-article pattern" instead of inheriting design from the SPA component (`MakcikGptArticle.tsx`). Section-label prefix lost.
3. **Caddy static-first fix exposed the drift.** When the static-first Caddy change was applied (see "Bot/browser false-positive trap" above), browsers started getting the static HTML — exposing the design gap that previously only bots saw.

### Recovery path: trace back via git history

**Step 1 — Find the lost `.ts` source in git.** Even when the file is gone from working tree, it usually exists in some past commit:
```bash
cd /root/arif-fazil.com && git log --all -- "**/<slug>*"
git show <commit>:<path>             # extract original .ts content
```
Verified: `syaitan-ingat-dirinya-malaikat.ts` existed in commit `1f6d380a` ("HUMAN_FIRST site constitution"). The `.ts` source contained `meta.domain = 'MAKCIKGPT × PETRONAS × AMANAH'` — which the SPA template interpolates into `Civilization Intelligence · Ξ WEALTH · {meta.domain}` to produce the section-label prefix.

**Step 2 — Read the SPA component as design SOT.** `src/pages/MakcikGptArticle.tsx` is the template that would render the article if registered. Key class names / structure to extract:

- Section-label: `<div className="section-label text-forge-red">Civilization Intelligence · Ξ WEALTH · {meta.domain}</div>`
- Title: `text-3xl md:text-5xl font-black italic uppercase leading-[0.9] tracking-tighter mb-4 mt-2` (no explicit color → inherits; user preference is `text-forge-red`)
- Subtitle: `font-technical text-sm text-forge-orange mb-4`
- Byline pills: `border border-forge-iron` (Bahasa Makcik pill) + `border border-forge-red text-forge-red` (Sealed pill) + `<time>`

**Step 3 — Identify the design delta.** Common drifts to look for in static HTML:

| Element | Static HTML (drifted) | SPA template (SOT) |
|---|---|---|
| Section label | `MAKCIKGPT × PETRONAS × AMANAH · SEALED 999` (single line) | `Civilization Intelligence · Ξ WEALTH ·` + `MAKCIKGPT × PETRONAS × AMANAH` (two lines) |
| Title color | `text-forge-white` | (none → inherits; user preference = red) |
| Title style | `font-display text-4xl md:text-6xl` | `text-3xl md:text-5xl font-black italic uppercase` |
| Subtitle color | `text-forge-white/70` | `text-forge-orange` |
| Subtitle font | `font-body text-lg md:text-xl` | `font-technical text-sm` |
| Byline first pill | `By Arif Fazil` | `Bahasa Makcik` (when `meta.language === 'ms'`) |
| Read-time pill | `· 3 min read` | (not in SPA template) |

**Step 4 — Patch the static HTML in place** (fastest, reversible):
```bash
patch the header section per Step 3 deltas
chown www-data:www-data /var/www/html/arif/makcikgpt-md/<slug>.html
chmod 644 /var/www/html/arif/makcikgpt-md/<slug>.html
curl -sL "https://arif-fazil.com/world/makcikgpt/<slug>?nocache=$(date +%s)" \
  -H "User-Agent: Mozilla/5.0" | grep -E "Civilization|Ξ WEALTH|Bahasa Makcik|italic"
browser_navigate → visual verify
```

**Step 5 — Optional: restore full SPA pipeline** (canonical integration). Save extracted `.ts`, register in `src/data/makcikgpt/index.ts` (both `makcikArticleModules` and `makcikArticlesMeta`), add to `src/data/essays.json`, then `npm run build` + rsync. Worth doing when the same drift affects multiple articles.

### Decision matrix — patch static HTML vs restore SPA registration

| Situation | Action | Rationale |
|---|---|---|
| Single article, no time pressure | Patch static HTML only | Fastest, reversible, T1 auto-do |
| Multiple articles same drift | Restore `.ts` + register + rebuild | One canonical fix, not N patches |
| Series needs design consistency | Restore `.ts` + register + rebuild | Pipeline integration keeps design tokens in sync |
| Design fundamentally changed (new color tokens, new section labels) | Update SPA component template first, then patch affected static HTMLs | SPA template is the SOT; static HTML follows |
| User wants the previous design but cannot articulate which elements | Show the reference screenshot's elements vs current diff in a table, ask user to confirm scope before patching | Avoids scope creep and preserves user agency |

### Anti-pattern: do NOT just re-deploy the .removed backup

Tempting to `cp /var/www/html/makcikgpt-md.removed-*/<slug>.html /var/www/html/arif/makcikgpt-md/` — but those backups reflect the SAME drift (verified: backup has identical simple kicker to the pre-patch static HTML). The drift predates the backup. Recovery is to read the SPA component template as design SOT, not restore an older version of the same drift.
