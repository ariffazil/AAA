## What changed in v3.1.0 (vs v3.0.x)

1. **Spine reorganised to 9 stages** accordant to `https://modelcontextprotocol.io/llms.txt`:
   - OLD: 1 DISCOVER → 2 PROBE → 3 INTEGRATE → 4 TEST → 5 GOVERN → 6 RETIRE
   - NEW: 1 LEARN → 2 DISCOVER → 3 PROBE → 4 BUILD → 5 SECURE → 6 TEST → 7 EXTEND → 8 PUBLISH → 9 GOVERN (with RETIRE sub-section)
2. **Stage 5 SECURE** is NEW. It absorbs the OAuth 2.1 / PRM / EAP / M2M / client-credentials surface from `tutorials/security/` + `extensions/auth/`.
3. **Stage 1 LEARN** is NEW. Orientation preamble before any operational work. Cites `architecture/`, `server-concepts`, `client-concepts`, `versioning`, `sdks/`.
4. **Stage 7 EXTEND** is NEW. Apps + Auth-extensions + Tasks + Skills-over-MCP.
5. **Stage 8 PUBLISH** is NEW. MCP Registry + Aggregators + Versioning + GitHub Actions + Authentication.
6. **Stage 9 GOVERN** absorbs SEP catalogue (16 active SEPs mapped to federation work), Working Groups + Interest Groups, SDK Tiers, Feature Lifecycle, Design Principles, sep-guidelines, Contributor Ladder, Security Policy, Antitrust.
7. **`mcp-testing` content** fully absorbed into Stage 6 TEST. `references/absorbed-mcp-testing.md` carries the body. `engineering/mcp-testing` becomes an inode-level symlink (verified 2026-09-21, sha matches `engineering/mcp-ops/SKILL.md`).
8. **22+ tombstone symlinks** verified alive (resolve to `engineering/mcp-ops`). 0 dead links.
9. **`aligned_to` field** added to frontmatter; lists the canonical sources the spine is accordant with.
10. **Negative triggers added** — Wealth MCP, Runpod MCP, TouchDesigner MCP, runtime-probe, agent-tool-verification, qwen-harness-tools all deflect to their sibling skills.
11. **Negative list expanded** — 12 forbidden actions (was 9). Adds: publishing without conformance, bearer tokens in SKILL.md, bypassing MCP-Protocol-Version envelope keys, deleting tombstones silently.

## Why v3.0.x → v3.1.0 was non-trivial

The v3.0.x skill was operationally excellent (every MCP-probe / MCP-build / MCP-test recipe in the
federation built on it) but **was not accordant to the canonical MCP project workflow**. A new
agent reading `https://modelcontextprotocol.io/llms.txt` would not arrive at the right stage in
v3.0.x — the spine used federation-friendly labels (DISCOVER → INTEGRATE → GOVERN) that don't
1:1 map onto llms.txt sections.

The v3.1.0 reorganisation makes mcp-ops the **canonical MCP operator for AAA AND for anyone
who arrived from upstream reading order** (llms.txt → mcp-ops SKILL.md). A new agent reading
llms.txt and loading mcp-ops finds the right stage trivially.
