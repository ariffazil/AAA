## Pitfalls that cost real time (each ~5-20 min lost)

### 1. `render-propa.cjs` hardcodes `public/propa/index.html`

Moving `public/propa/` → `public/world/propa/` broke `npm run build` with ENOENT on the
old path. Fix: `sed -i 's|public/propa|public/world/propa|g'` in every render script.
WARNING: sed on the already-patched path double-prefixes (`public/world/world/propa`) —
grep-verify after sed. Same pattern for `dist/propa/` → `dist/world/propa/`. Files
affected: `scripts/render-propa.cjs`, `scripts/generate-ns-compare.cjs`.

### 2. `infra/runtime-overlays.json` required_artifacts check

`deploy-site.sh` aborts with "required artifact missing: $root/$artifact" if the
overlay lists a path the new dist doesn't have. The `sites` field is a LIST of dicts
(not a dict-of-dicts), so the patch needs to iterate the list. Symptom: build + deploy
both green, but final deploy fails on the artifact check. Affected entry:
`999/index.html` → `work/proof/index.html`.

### 3. Caddy `@static_dirs` requires file in webroot, not just path listed

Adding `/words/ /work/ /propa/` etc. to `@static_dirs` makes Caddy willing to serve
those paths, but `try_files {path} {path}/ =404` means if the actual `index.html`
isn't in webroot, you still get 404. Sequence MUST be: build → deploy → probe.
Listing the path alone gives you a *capability*, not a serving.

### 4. `curl --max-redirs 0` exits 47 on 308 — false negative in loops

When verifying redirects, don't pass `--max-redirs 0`. The 308 exit code is treated as
an error and breaks the loop. Use two separate calls:
```bash
curl -s -o /dev/null -w "%{http_code}\n"        # the code
curl -s -o /dev/null -w "%{redirect_url}\n"    # the target
```

### 5. `<noscript>` fallback in `dist/index.html` still shows old nav

The React SPA bundle has the new 5-item nav. But `dist/index.html` (the static
SSR default) has its own `<noscript>` block with the old "Build/Decide/Interpret"
labels. Static HTML pages (`/words/`, `/work/`, `/world/`) carry their own
`<nav class="nav">` — patch each. The root static index needs its own patch if you
care about SSR.

if >0, a sibling deployed the feature. Reconcile, don't re-inject. The v3 paradox

## Build pipeline gotchas (specific to reorg)

The npm build pipeline is `prebuild → tsc → vite → postbuild (copy-static-html.js
+ render-propa.cjs + generate-ns-compare.cjs)`. The postbuild step hardcodes
dist paths — when you reorg, BOTH the source-tree paths AND the dist-tree paths
must be patched. Easy to miss the second one.

`render-propa.cjs` warnings ("marker ... not found — skipping") are noise after
v3 replaced the markers; build still succeeds but the SVG injector outputs nothing.
The marker-not-found warning is harmless post-reorg.

## Caddyfile patches (sticky rules)

After major edits, `caddy fmt --overwrite` to fix whitespace. `caddy validate`
prints "Valid configuration" on success — ALWAYS check that line before reload.
The single warning "Caddyfile input is not formatted" is benign until
`caddy fmt` is run; it does not break reload.

`@static_dirs` lists paths *explicitly*. New lanes (e.g. `/words/` `/work/`)
need both the dir AND both bare + trailing-slash forms. Same for all new
subdirs you expect to serve as static (`/propa/*`, `/malaysia/*`, etc).

## Validation gate (full reorg)

```bash
# 1. Live targets all 200
for p in / /earth/ /words/ /world/ /work/ /words/doctrine/ /words/writing/ \
         /words/constitution/ /world/propa/ /world/malaysia/ /world/politics/ \
         /world/economics/ /world/economics/oil/ /world/economics/gold/ \
         /work/missions/ /work/proof/ /work/wells/ /work/resume/; do
  code=$(curl -s -o /dev/null -w "%{http_code}" "https://arif-fazil.com$p")
  [ "$code" = "200" ] || echo "MISSING: $p → $code"
done

# 2. Legacy 308s
for p in /writing/ /doctrine/ /essays/ /propa/ /malaysia/ /politics/ /oil/ \
         /gas/ /gold/ /klci/ /usdmyr/ /economics/ /missions/ /999/ /vitals/; do
  code=$(curl -s -o /dev/null -w "%{http_code}" "https://arif-fazil.com$p")
  [ "$code" = "308" ] || echo "WRONG: $p → $code"
done
```
