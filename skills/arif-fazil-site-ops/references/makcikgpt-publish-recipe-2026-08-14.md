# MakcikGPT Article Publish Recipe — 4 Registers

> Verified 2026-08-14. Distinct from essay publish recipe (5 registers).

## The 4 registers

| # | File | What it does |
|---|---|---|
| 1 | `src/data/makcikgpt/<slug>.ts` | Article body as `ArticleContent` (slug + html backtick template literal) |
| 2 | `src/data/makcikgpt/index.ts` | THREE edits: (a) `import` line, (b) add to `makcikArticleModules` array, (c) add full meta to `makcikArticlesMeta` array |
| 3 | `src/data/essays.json` | Add entry with `"lang": "bm"`, `"dest": {"type": "onsite", "path": "/world/makcikgpt/<slug>"}`, `"id": "m2-9"` style |
| 4 | `public/makcikgpt-md/<slug>.html` | Pre-rendered static HTML for bot UA serving |

**Critical:** Register 4 is generated by `scripts/generate-makcik-articles.cjs` which reads from `essays.json` (via `makcik-source.cjs`). Run it AFTER patching essays.json. Then `npm run build` to bake the article into the SPA JS bundle.

## Build + deploy + verify

```bash
cd /root/arif-fazil.com/sites/arif-fazil.com

# 1. Generate bot-serving HTML from essays.json
node scripts/generate-makcik-articles.cjs

# 2. Rebuild SPA (bakes article into JS bundle)
npm run build

# 3. Deploy
cd /root/arif-fazil.com && bash scripts/deploy-site.sh arif-fazil.com --apply

# 4. CRITICAL: Force-sync assets (deploy-site.sh doesn't always sync JS bundles)
rsync -av sites/arif-fazil.com/dist/assets/ /var/www/html/arif/assets/
cp sites/arif-fazil.com/dist/index.html /var/www/html/arif/index.html

# 5. Verify all 3 surfaces
curl -s -H "User-Agent: GPTBot" "https://arif-fazil.com/world/makcikgpt/<slug>" | grep -c "<title>"
curl -s "https://arif-fazil.com/world/makcikgpt/" | grep -c "<slug>"
curl -sf https://arif-fazil.com/feed.xml | grep -c "<slug>"
```

## Sibling clobber recovery (2026-08-14)

A sibling agent's commit or deploy can silently overwrite all 4 registers. Symptoms:
- `getMakcikSource()` returns correct count (e.g., 23) but live page shows fewer (e.g., 22)
- `.ts` file missing from `src/data/makcikgpt/`
- `index.ts` import + array entries missing

**Recovery path:**
1. Check `/tmp/` for staging files from the original session (they survive between sessions)
2. Check `forge_work/deployments/<tag>/previous/makcikgpt-md/<slug>.html` for article HTML
3. Re-create all 4 registers from backup content
4. Rebuild + redeploy + force-sync assets

## Common bugs

| Bug | Cause | Fix |
|---|---|---|
| `decodeTasksToEnvelopes is not defined` | Missing import in server.js | Add to require destructure |
| Article renders in bot UA but not browser | JS bundle hash mismatch (deploy didn't sync assets) | Force `rsync dist/assets/ → /var/www/html/arif/assets/` |
| Index shows N-1 articles | Sibling clobbered one register | Check all 4 registers individually |
| User says "not live" but curl shows correct | Browser cache on phone | Tell user to clear history or use `?v=2` cache-buster |

## JS bundle verification

After deploy, verify the live bundle contains the article:
```bash
# Check bundle hash match
grep -oE 'assets/index-[^"]+\.js' /var/www/html/arif/index.html
# Should match the dist bundle
ls /root/arif-fazil.com/sites/arif-fazil.com/dist/assets/index-*.js
# Verify article content in the live bundle
grep -c "<slug>" /var/www/html/arif/assets/index-*.js
```
