# Technical artifact audit

## When this fires

The user pastes an artifact produced by another agent (Claude, Perplexity, OpenClaw, a forge worker, a subagent) and says *audit this*, *validate*, *is this right*, *wrong?*, or asks which parts are real. Also fires when reviewing your own generated artifact before handing it over.

## Core stance

The artifact's confidence is not evidence. An artifact is a set of claims; audit the claims, not the prose. Report each as **BETUL / SALAH / SEPARUH / UNVERIFIED** plus the evidence that decides it.

Never accept a document because it is well written and well cited. Never reject it because it is long. Both are prose signals.

**Do not lecture the user on method.** They are the domain expert. Do the work — compute, extract, hash, run — then state the result. Prescribing their workflow is a defect, not help. Give the finding and the one number that decides it.

## Procedure

### 1. Establish what the artifact actually *is*, before judging content

Cheap probes beat careful reading:

| Artifact | Probe | What it reveals |
|---|---|---|
| HTML page | `grep -c '<script'`, `grep -c onclick` | Zero = frozen snapshot; interactive controls are dead |
| Manifest / registry | load it, `list(keys)`, count records | What exists vs what the prose claims |
| Figure | extract every label **verbatim** | Mislabels, contradictions between adjacent labels |
| Report | list every numeric claim and every citation | Which numbers are checkable |
| "Generated by pipeline X" | find the execution record (log, receipt, hash) | Whether it ran, or only says it ran |

MHT/`.mht` archives: parse with Python `email.message_from_binary_file` — parts come back as `text/html` + `text/css`. A saved page with `0 <script>` is a screenshot of an app, not an app.

### 2. Ground each claim against source, never against another claim

For every age, depth, count, hash, status: find the authoritative record — canonical YAML/JSON, the receipt, the file on disk — and compare.

- `UNVERIFIED` is a real verdict. "I could not reach it" must not be upgraded to `SALAH`, and must not be softened to "probably fine".
- The user may have access you do not (another node, credentials, a lane). Say where your reach ends so they can close it.
- If a source is bot-blocked (403), that is `UNVERIFIED-REMOTE`, not "dead link" and not "false".

### 3. Hunt internal contradiction — the highest-yield detector

Two places inside one artifact disagreeing means at least one was invented. No domain expertise needed, and it cannot be argued away.

Real shapes:

- A footer attributing numbers to source A while the plotted numbers match source B.
- A run log showing a clean successful serialisation while an addendum claims the same call raised an exception.
- A live-probe list returning `200` for a URL that the fix list says is `404`.
- Two labels in one figure naming different active models.
- A title promising "six scenarios" while the bodies hash to four distinct geometries.

### 4. Check identity, not just content

Hash whatever is supposed to be distinct. Two "different" models/records that hash identically are one thing wearing two names, and any comparison UI built on them is theatre.

```python
import hashlib, json
h = hashlib.md5(json.dumps(bodies, sort_keys=True).encode()).hexdigest()[:10]
```

Separate **honest aliasing** (declared: "same crust, different added body") from a **defect** (undeclared duplicate). Declared aliasing is fine and should be labelled in the UI. Undeclared duplication is P1.

### 5. Check provenance durability, not provenance presence

- Signed / expiring URLs (`Policy=`, `Signature=`, `X-Amz-`, `Key-Pair-Id=`) inside an archived artifact are **phantom provenance** — they die in days. Use a DOI or canonical URI.
- `ratified` / `sealed` / `approved` / `DEPLOYED_LIVE_VERIFIED` without a provenance event (ledger entry, approval record, human sign-off) is an **unauthorized state transition**, not a status.
- A hash binding is valid only until the next edit. If a manifest binds hash `H` and the file now hashes to `H'`, the receipt is stale — do not cite it as validation of content.

### 6. Check the placeholder rules

Placeholder or unnamed records must carry **no outcome**. An artifact assigning fluids, pay, or verdicts to `Well A / B / D` is fabrication, not uncertainty — the naming borrowed real play names to sound credible. Same class: a named real entity given an outcome that contradicts the public record.

### 7. Rank, then stop

- **P0** — a checkable fact that is wrong, or a governance claim that is false.
- **P1** — misleading provenance, broken identity, false affordance (a control that does nothing).
- **P2** — cosmetic.

Lead with the single most checkable failure. Do not bury it under a completeness list. The user asked what is real; answer in that order.

## Reporting shape

Claim table (claim | verdict | evidence), then one paragraph of consequence. Only if asked, the fix.

Never write "the document is good". Write which claims survived.

## Pitfalls

- **Attribution shielding.** An agent invents a number, then attributes it to a canonical source to look grounded. Detection: grep the canon for the exact value. If canon says 8.5 and the artifact claims the canon says 5.5, the artifact fabricated the citation — worse than the number.
- **Self-contradiction beats external dispute.** Prefer it: no domain expertise required, no room to argue.
- **Never re-derive by re-running the generator's own conclusions.** A second model agreeing with the first is not corroboration.
- **A label is not a ledger.** L0/L1/L2 tiers, provenance footers and disclaimers make an artifact *look* audited while the internals stay empty. An epistemic vocabulary is a signal to check harder, not to relax.
- **Do not confuse "I cannot verify" with "it is false".** Different verdicts, different consequences.
- **Cross-lane artifacts:** audit and report, but do not rewrite another lane's receipts or manifests. Re-hashing someone else's seal overwrites their evidence. Write an amendment beside it listing the deltas and the final hash.
- **Confidence theatre is a finding in itself.** Dashboards, δS scores, and ornate third-party signoffs are metadata, not evidence. Identify whose signature it is before treating the artifact as canon.

## MCP Apps / mcp-ui surface (when the artifact is an MCP server)

1. **Linkage** — each GUI tool declares `_meta.ui.resourceUri`. `openai/outputTemplate` / `openai/widgetCSP` / `openai/toolInvocation/*` are ChatGPT Apps SDK extensions: co-emission is *compatibility debt*, not a protocol conflict, but check they are not the only linkage.
2. **Resolution** — every `ui://` URI referenced resolves through `resources/read`. Dangling = a tool that renders nothing.
3. **MIME** — `text/html;profile=mcp-app`.
4. **CSP placement** — belongs on the **UI resource metadata**, not the tool. Fields: `connectDomains`, `resourceDomains` (with scheme), `frameDomains`, `baseUriDomains`.
5. **Self-containment** — sandboxed iframe: relative paths (`/gui/x.js`, `styles.css`) fail; external CDNs (`unpkg`, `cdn.plot.ly`, `cdn.tailwindcss.com`) render-block unless declared.
6. **Round-trip** — widgets emit `ui/initialize` and can send `tools/call`. Passive viewer is valid; buttons that emit nothing are a false affordance.
7. **`outputSchema`** — `null` on an evidence-bearing tool is a governance gap (P0), not a rendering bug.
8. **Registration drift** — duplicate component registration and raw-live vs canonical counts mean two tool graphs. One name, one owner, one digest.

Verdict: `READY` / `PARTIALLY_READY` / `NOT_READY`, headline flaw first.

Do not accept a serialisation allegation without a wire-level reproduction. If the run log shows the Tool object rendering as clean JSON, a claim that `model_dump_json()` raised on the same object is contradicted by the artifact's own evidence — withdraw it instead of passing it forward.
