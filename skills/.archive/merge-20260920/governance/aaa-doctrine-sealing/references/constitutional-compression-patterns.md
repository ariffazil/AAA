## Pattern: Theory → Floor → Kernel → Invariant

```
69 scattered theory files
  ↓ (map each to one of 13 reality-defenses)
13 Constitutional Floors
  ↓ (compress to one boot-loadable artifact)
1 GODEL_LOCK::INIT (boot screen)
  ↓ (single invariant underneath)
1 Invariant: Reality > Everything
```

### When to apply
- F13 says "compress" or "this is getting too many files"
- More than ~30 files reference one principle from different angles
- A boot sequence would need to load 10+ fragments to cover the same ground

### The test
If a new agent can read ONE file (one screen, <200 lines) and understand the constitution, the compression is complete. If it needs 5+ files, it is not compressed — it is scattered.

## Pattern: Intuition → Formalization (Moral Physics)

```
Human intuition ("don't be a jerk")
  ↓ (extract the constraint, not the feeling)
Physics formulation (dignity = state vector, violation = projection)
  ↓ (encode as operators)
Math formulation (V(a,h) = a·D×cos(θ), CS = ∏constraints)
  ↓ (make executable)
Code (MaruahRuntime class with dignity_state, violation_check, entropy_check)
```

### When to apply
- F13 says "can we code that?" about an intuition or moral concept
- A principle is clear in conversation but has no machine-readable form
- The gap between "everyone knows this" and "no agent can check this" needs bridging

### Key constraint
Formalize the CONSTRAINT (what to avoid), not the FEELING (what to experience).
- Dignity: don't violate the state vector → codeable
- Love: feel connection → not codeable
- Common sense: check six constraint layers → codeable
- Wisdom: ??? → not codeable (wisdom = judgment, not constraint)

### Pitfall
Formalization is the SENSOR, not the AGENT. The code detects violations; it does not choose responses. Never present a formalization as "solved morality" — it is "measurable constraint compliance." The human still decides.
