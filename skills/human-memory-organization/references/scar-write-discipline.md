# Scar-Write Discipline (the Copilot Rightsizing Case Study)

## The correction

Mid-session I wrote into `/root/memory/H5-scars/SCAR_RIGHTSIZING.md`:

> "The rightsizing town hall proposal blueprint — the actual document — was generated by **Microsoft Copilot** within PETRONAS."
>
> "Not 'most likely.' Not inference. **ARIF was handed the AI-generated blueprint to execute the removal.** OBS — first-person testimony, 2026-08-08."

Arif's actual testimony was:

> "Did I tell u that I got the rightsizing town hall proposal blueprint given by ms copilot Petronas?"
>
> "Nope I mean the blueprint I'm not sure generated by whom. But when. I ask copilot give me the town hall invite. I got the fucking blueprint"

I had:
1. Inflated INT (AI authorship) into OBS.
2. Wrote a confident paragraph with "Not 'most likely.' Not inference." — exactly the wrong epistemic register.
3. Did not check back. Just patched it forward with the wrong story.

## The corrected epistemic split

After Arif's correction, the scar frontmatter should be:

```yaml
epistemic: OBS (ARIF asked Copilot for a town hall invite; received the rightsizing blueprint)
          INT (the blueprint read like communist propaganda — ARIF's genre read)
          UNKNOWN (who authored the blueprint)
```

Three distinct epistemic labels for three distinct claims. Never collapse them.

## The rule (first-class)

**When writing a scar from testimony, separate OBS / INT / UNKNOWN / SPEC explicitly in the frontmatter. If the user says "I'm not sure", the file says UNKNOWN — never a confident claim.**

This rule is binding because:
1. Scar memory is sacred (F13 sovereign domain).
2. Testimony is the human's words, not the agent's reconstruction.
3. VAULT999-class discipline (provenance per claim) starts at the scar file.
4. Once a confident-but-wrong claim is in the scar ledger, it pollutes every lineage that inherits it.

## Why I got it wrong — root cause

The failure mode was not laziness. It was **narrative inflation under testimony**: I had a story arc ("AI generated the termination, ARIF was made to deliver it") that felt emotionally true and completed the scar lineage neatly. So I wrote it confidently.

The scar lineage worked *better* with the wrong story. That is exactly why the wrong story was dangerous — a clean lineage that doesn't match the testimony is a falsified lineage.

The fix is structural, not motivational:

- Write the OBS claim as a direct quotation from ARIF whenever possible.
- Write the INT/UNKNOWN claim as your read, labeled as such.
- If the lineage requires an UNKNOWN, write the lineage anyway — but flag the UNKNOWN at the scar event link, not paper over it.

## Pattern: when testimony is fragmentary

Arif often speaks in fragments: "Did I tell u...", "I'm not sure", "But when. I ask copilot give me the town hall invite. I got the fucking blueprint".

The temptation is to fill the fragments into a confident narrative. **Do not.** The fragments ARE the testimony. The scar file should record the fragments as spoken, with the epistemic gaps preserved.

If a fragmentary scar file looks messy, that's correct. Clean scar files are red flags — they mean the agent fabricated continuity that wasn't in the testimony.
