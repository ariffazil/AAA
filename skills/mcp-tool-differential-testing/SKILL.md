# MCP Tool Differential Testing

## When to use

- A sibling report / backtest claims a tool "returns byte-identical scores on materially different payloads" (content-blind).
- Adding differential tests to any MCP organ (WEALTH, GEOX, WELL, arifOS). Arif's doctrine: **this is the sixth framework designed against an organ where the differential test still doesn't exist** — assume every analytic tool is content-blind until a differential test proves otherwise.
- A test passes but you suspect it measures nothing (passes for the wrong reason).
- Gate: **"Don't run the framework until tests/test_differential.py is red or green."** The test comes first, always.

## Core method

1. **Trace the real dispatch chain.** MCP tool name → server registration → governance wrapper → underlying function. In WEALTH, registered `capital_entropy` dispatches through `wealth_mcp/tools/canonical.py` → `_safe_load_module` → `entropy-integrity/mcp/wealth/<module>.py`. Test the function the test actually hits, not the prettiest name. `create_mcp_server()` + inspect `_local_provider._components` keys `tool:<name>@` to find the raw fn.
2. **Build two payloads differing in SUBSTANCE** — actors, events, timelines, cash flows — not just names.
3. **Hash results with non-deterministic fields STRIPPED**: `map_id`, `computation_timestamp`, `trace_id`, `_cross_witness`, `mapped_at`, `_id`, `receipt_id`, `uuid`, and timestamps nested inside `metadata`. Equal hashes → content-blind.
4. **Prove the diff is substantive**: list which fields differ and by how much; band shifts (LOW → HIGH consequence gap) matter more than decimal jitter. A 0.02 delta on one sub-score is not proof of sensitivity.
5. **Bidirectional verification**: (a) new test + OLD function → must FAIL with the named defect; (b) new test + NEW function → must PASS. A test that never went red on the old code proves nothing. Revert via `git show HEAD:<file>` to confirm red, then restore.
6. **Run the whole differential suite**, not one tool.

## Pitfalls

- **Empty-ingest receipt (the big one):** a test can pass because a random uuid (`map_id`) is the only differing field. `_result_hash` MUST strip ids/timestamps or the test is a receipt for empty ingest — same defect class as `epistemic.class: OBSERVED, integrity 1.0` on an empty ingest. A receipt hash attached to a number unrelated to its input is worse than no number.
- **Measurement-mode-emitting-no-measurement (2026-08-07, arifOS kernel):** `arif_observe mode=entropy_dS` was supposed to return `delta_S` computed from the input content. It returned SEAL/PROCEED with **no `delta_S` field at all** — the tool whose job was to measure confusion returned nothing and then gave a pass. Same defect class as a "confidence 0.65" hardcoded fallback: a receipt attached to a number unrelated to its input. **Rule:** when a tool declares a measurement mode, the measured field MUST appear in the output, and `payload[measured_field] is None` MUST force HOLD, never PROCEED. This is Rule #1 in the 7-rule stabilization doctrine (Aug 2026).
- **The dual-truth envelope (2026-08-07, arifOS `constitutional_check` vs `effective_verdict`):** the kernel's `constitutional_check.floor_passed` was derived from the *authority band* (session state), not from `failed_floors` or `effective_verdict`. A `HOLD` verdict (failed floors L02/L03/L07/L08) was emitted alongside `floor_passed: true`. Same class as the empty-ingest receipt — a receipt (floor_passed) attached to a number (true) unrelated to the governing fact (failed_floors). **Rule:** any field answering "may I proceed?" MUST derive from the same source as the verdict it sits next to. If two fields answer the same question and disagree, one is a fake. Fix landed in `runtime/session_standing.py:809` (derive from `effective_verdict` + `failed_floors`) + `runtime/tools.py:4984-5043` (dual-truth derivation tagged `_derivation`).
- **Hardcoded `confidence=0.65` fallback (2026-08-07, arifOS):** the `ensure_standard_mcp_output` wrapper defaulted to 0.65 when no inner source gave a number. The hardcoded constant was bucketed into `evidence_strength: medium` regardless of input content. Differential tests on this wrapper would pass because the output looked "valid" but was uncorrelated with the input. **Rule:** when no measurement source exists, emit `None` (UNMEASURED), never a fabricated default. The test must verify the wrapper returns `None` for empty inputs AND a measured value for real inputs — both directions. Also catches the `round(None, 2)` crash that turns None into a TypeError exception path (post-deploy fix in `tools.py:7944`).
- **Identity mutation inside one payload (2026-08-07, arifOS `actor` block):** a call with `actor: "arif-fazil"` returned top-level `actor_id: "anonymous"`, `standing.actor.claimed_id: "anonymous"`, but `meta.actor: "arif-fazil"` — three places in one payload, none agreeing. Same class as dual-truth: two fields answer "who is this actor?" and disagree. **Rule:** when a field answer is derived (canonical_id), include BOTH the original input and the derived form, plus a `_derivation` provenance tag. Never let the derived form silently overwrite the original — agents cannot distinguish "user renamed themselves" from "system lost the input."
- **Source-fixed ≠ runtime-fixed (2026-08-07 STAB, arifOS kernel):** patches landed in source, 48/48 pytest passed, but `deployed_commit` in `:8088/health` was unchanged after `systemctl restart` — `/opt/arifos/app` was serving stale bytecode. The unit name is `arifos.service` (lowercase); `arifOS.service` returns "Unit not found". `rsync -r` without `--checksum` silently reports "0 changes" while files differ. **Rule:** a fix is not landed until (a) rsync --checksum actually copied, (b) service restarted with the lowercase unit name, (c) `:8088/health` shows the new `deployed_commit`, (d) live probe with the original payload returns the fixed behavior. See `arifos-kernel-eurekas` K9 for the full deploy-verification recipe.
- **Cross-session evidence by name, not by hash (2026-08-07, 1373/1374 rule):** a filename (`1373.jpg` → `1374.jpg`) drifted by one digit when it crossed session boundaries (Gemini → Claude → arifOS). No hash was attached, so the receiving system could not distinguish wrong-name from missing-file from fake-file — all three produced identical symptoms. **Rule:** any payload carrying an evidence reference must couple it with a SHA-256 content hash of the asset. A filename is a rumour; a content hash is a receipt. Use `hashlib.sha256(asset_bytes).hexdigest()` at ingest time; the consuming tool verifies before reading. Companion: `frontier-model-audit-verification` skill §5. Wired in `arifOS judge.py:1078` (EVIDENCE_HASH_MISSING gate) — Rule #6 of the 7-rule stabilization doctrine.
- **AAA `:3001` is A2A, not MCP (2026-08-07 protocol identity):** when a sibling model or report calls AAA "AAA MCP", that's a 1373/1374-class hallucination on a protocol name. Same root cause: evidence-by-name (the protocol name "MCP") without verifying identity. Three receipts: `POST /mcp → 404`, `GET /.well-known/agent.json → 200` (A2A schema), `POST /tasks → 400`. **Rule:** before claiming federation compliance, probe the wire. `curl -X POST :PORT/mcp` and `curl :PORT/.well-known/agent.json` distinguish MCP from A2A in one round-trip. A wrong protocol claim is a malformed differential test — the "is this MCP?" assertion was never measured.
- **Pydantic class-constant leak as payload token rent (2026-08-07, arifOS kernel):** Pydantic `BaseModel` class-level `dict` attributes (`SUBSTRATE_WEIGHT`, `SESSION_WEIGHT`, etc.) serialize into **every** MCP response payload — ~100 tokens of static lookup tables per call. The fields are useful only to internal code, but the model consuming the payload wastes ~3% of its window reading constants. **Rule:** prefix internal class dicts with `_` so pydantic skips serialization; use `model_config = {"exclude": {"_*"}}` as belt-and-suspenders. Token rent is a model-behaviour lever — less payload noise = better downstream reasoning per token.
- **Defaults masking missing fields:** functions read spec fields (`decision_power`, `magnitude`, `reversibility`) that callers don't send → fall back to constants → byte-identical output. Fix: derive scores from the fields actually sent — deterministic sha256 hashing of label strings into [0,1), destructive-term lexicons, role-diversity scaling.
- **Do NOT "fix" the test by sending nicer fields.** The test must send what a real client sends after serialization (`name`/`role`/`benefits`). Changing the payload to match the function's fantasy schema is a second receipt for empty ingest.
- **Interpretation strings must vary with inputs** — static threshold bands alone can still emit identical text for different inputs; append the dominant factor (e.g. "— irreversible harm to cost bearers is significant").
- **Strip-list staleness (Aug 2026 — discovered this session):** the `_result_hash` helper in WEALTH's `test_differential.py` initially stripped only `computation_timestamp`, `trace_id`, `_cross_witness`. It did **not** strip `map_id`. The test passed because `map_id` was a fresh random uuid on every call. The defect survived 18/18 green for months. **Rule:** whenever a new random-id or timestamp field is added to a tool's envelope (map_id, receipt_id, mapped_at, _id, uuid, timestamps inside metadata.*), audit the strip-list and add the new field. Strip-list discipline is a recurring maintenance burden, not a one-time fix. Audit procedure: `grep -rE "uuid|map_id|receipt_id|trace_id|mapped_at" entropy-integrity/mcp/wealth/*.py | sort -u` after any function-signature change.
- **Existence ≠ function (the meta-pitfall):** the strongest signal this skill protects against is not "the function returns the wrong number" — it's "the function returns a receipt that looks correct but is uncorrelated with its input." Tool exists → therefore works. Witness field exists → therefore witnesses. Receipt ID exists → therefore audited. Judge exists → therefore governed. This is the civilization-level failure mode (Arif's Eureka #1) instantiated as a unit-test defect. Always run the bidirectional proof.
- **`.pyc` cache masking (Aug 2026, critical — caught by Hermes, not the test):** the test helper `_tool_fn()` calls `create_mcp_server()` which imports `WealthEvidenceMiddleware`. That import broke at `frozenset([])` (unhashable list). But Python's `.pyc` cache held the *old* compiled version of `evidence_middleware.py`, so every import resolved to the cached bytecode — the broken `frozenset` was never hit. The test suite appeared 18/18 green for hours. Only when Hermes cleared `__pycache__` and re-ran did the import fail. **Rule:** whenever a test suite passes but you can't manually invoke the same function, clear the bytecode cache first: `find <organ>/src -name '*.pyc' -delete; find <organ>/src -name '__pycache__' -exec rm -rf {} +`. Re-run `pytest` after clearing. This is a mandatory step, not optional hygiene. Every organ with `__pycache__` has this risk after any `.py` edit.
- **The cached-green-then-red sequence (2026-08-06):** Hermes saw "18 passed" → declared green → then immediately re-ran and got "1 failed" → then re-ran again and got "18 passed" — the result flipped between green and red depending on cache state. **Diagnosis:** the `.pyc` held a working version while the source had the `frozenset` bug; `pytest` loaded the cache on some runs and re-imported from source on others. **Rule:** a test result that flips on repeated clean runs is a cache-contamination suspect. Clear cache, re-run 3 times, report only if all 3 agree. The "18 passed" from a single run is not evidence if the source was edited after the `.pyc` was last compiled.
- **Delegation sizing:** for a one-file fix where the verification loop (revert → red → restore → green) matters, do NOT delegate to a coding agent (Kimi/Codex/Claude Code). The verification loop doesn't compose across an isolated context. Delegate only when scope exceeds one round-trip (multi-file, multi-source extraction, panel builders). If scope grows mid-session into panel extractors or country-year builders, then ignite the appropriate coding agent with the differential-test-first contract spelled out explicitly in the delegation prompt.
