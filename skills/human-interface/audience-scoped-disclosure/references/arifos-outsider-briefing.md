# Briefing a visitor on arifOS — carve-out and skeleton

Companion to `audience-scoped-disclosure`. Use when Arif asks you to tell a third party about the
system, or when a visitor reading the thread asks directly.

## The include/exclude carve-out

**Include (the outside layer):**

- **What it is** — a governance layer between a human and a model. The model thinks; the layer
  decides whether a thought is allowed to become an action.
- **Why it exists** — agents forgot who they were, what they were permitted, and who was in charge.
  So the constitution became a gate rather than a document. The founding line, safe to quote:
  unbounded intelligence is dangerous not because it is evil, but because it is competent without
  allegiance.
- **Separation of power** — four separate bodies, none able to do the others' work: display / judge /
  execute / remember. A display plane that cannot adjudicate; a kernel that judges; an execution
  shell that only runs what passed; a ledger that only appends.
- **Organs as roles** — kernel, cockpit, execution, earth intelligence, capital, human readiness,
  bridge. Roles only, never hosts.
- **The floors as a named list**, one line each — the shape, not the implementation. Give the most
  weight to the unusual ones (no ghost in the machine; the agent is not a person; the human veto is
  final).
- **Consent and witness** — the human's veto is final and unqualified; silence is not consent; no
  system adjudicates itself, the witness must come from outside. One sentence each.
- **What it is not** — not a product, no investors, no commercial roadmap. A personal system.

**Exclude by default (private layers):**

- Any doctrine derived from a personal scar, and the trauma-derivation material behind the floors.
- Machine topology — hosts, IPs, ports, paths, service names, container or deployment shape.
- Arif's professional/institutional context, employer, colleagues, live projects.
- Health, family, relationships, other people's dossiers, anything drawn from a private lane.
- Secrets, keys, tokens, config contents, ledger contents, incident and audit history.
- Internal doctrine paths, the canon directory shape, internal agent names.

Boundary test: **how it works** is private; **what it is for** is public.

## Vocabulary translation table

| Internal | Say to the visitor |
|---|---|
| kernel / `arif_*` verbs | the part that judges |
| lane / alias names | (omit — never name lanes) |
| floors / F1–F13 | the thirteen rules, by plain name |
| seal / the ledger | the permanent record |
| HOLD / VOID / SEAL | stopped, rejected, approved |
| organ / warga | component |
| the sovereign | Arif / the human who owns it |

## Briefing skeleton (proven shape)

```
What it is            — one paragraph, no jargon
Why it exists         — the founding problem, one or two sentences
Separation of power   — four bodies, one line each
Organs                — the roles, not the hosts
Floors                — named list, one line each
Consent and witness   — human final veto; no system adjudicates itself
What it is not        — not a product
```

Keep it shorter than feels complete. A visitor who wants depth will ask, and each follow-up lets Arif
decide how much further in they go.

## Closing move

Hand back to Arif on its own line: what you deliberately left out, and that it is his to open. Do not
list the exclusions inside the visitor's message — that list is for Arif.

## Checkpoints before sending

1. Did the identity pre-check run, and is the person's record real or absent? (Absent stays absent.)
2. Is every sentence in the visitor's part free of topology, private lanes, and internal names?
3. Is the register neutral — no kampung markers, no in-jokes aimed at the visitor?
4. Is there exactly one hand-back line to Arif, naming what was withheld?
