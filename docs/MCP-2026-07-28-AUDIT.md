## 1. Executive Summary

MCP specification `2026-07-28` is a **major compatibility boundary**. The protocol is now stateless-first: no `initialize` handshake, no `Mcp-Session-Id`, every request self-describing. Our federation has **one compliant organ** (arifOS), **one legacy organ** (A-FORGE), and **four untested organs** (AAA, GEOX, WEALTH, WELL).

**Critical finding:** A-FORGE's session-bound transport is the federation's principal protocol bottleneck. It conflicts with the current core model.

## 2. MCP 2026-07-28 — What Changed

### 2.1 Breaking Changes

| # | Change | Spec Reference |
|---|--------|---------------|
| 1 | **Stateless core** — `initialize`/`initialized` RETIRED, `Mcp-Session-Id` REMOVED | SEP-2575, SEP-2567 |
| 2 | **`server/discover`** RPC — MUST implement (clients may skip) | New RPC |
| 3 | **`Mcp-Method` required** on all Streamable HTTP; **`Mcp-Name` required** for `tools/call`, `resources/read`, `prompts/get` | SEP-2243 |
| 4 | **Header/body consistency** — server MUST validate headers vs JSON-RPC body; mismatch → HTTP 400 / `-32020` | Anti-confused-deputy |
| 5 | **MRTR** replaces server-initiated elicitation/sampling/roots | SEP-2322 |
| 6 | **List results cacheable** — `ttlMs` + `cacheScope` required; deterministic ordering | SEP-2549 |

### 2.2 Auth Hardening

- RFC 9207 `iss` validation (SEP-2468)
- CIMD replaces DCR (SEP-991)
- Client credentials bound to issuer (SEP-2352)

### 2.3 Deprecations (12-month window)

- **Roots** — filesystem scope boundary gone
- **Sampling** — replaced by MRTR
- **Logging** — replaced by extensions
- **Legacy HTTP+SSE** — replaced by Streamable HTTP

### 2.4 New Extensions

- **Tasks** (`io.modelcontextprotocol/tasks`) — async long-running ops
- **MCP Apps** — servers ship interactive HTML to agents
- **Enterprise Managed Authorization (EMA)**

### 2.5 Security Risks

| Risk | Control |
|------|---------|
| Handle hijacking | Signed, scoped, expiring, non-enumerable handles; actor binding; replay detection |
| Filesystem scope gap | OS/container mount policy; canonical-path allow-list; deny-by-default writes |
| MCP Apps XSS | Sandboxed iframe; strict CSP; no direct credential access |
| Header/body split-brain | Enforce `Mcp-Method`/`Mcp-Name` parity; reject `-32020` |
| OAuth issuer mix-up | Validate `iss` before code redemption |
| Legacy fallback abuse | Explicit version policy; no fallback on modern errors |

## 6. Handle Security Model

### 6.1 Requirements

Server-minted handles passed as ordinary tool arguments. Model-visible = disclosure-prone.

### 6.2 Handle Format

```json
{
  "workflow_handle": "wf.v1.<256-bit-opaque-random>.<HMAC-signature>",
  "expires_at": "2026-09-04T14:30:00Z",
  "scope": ["geox:read", "well:correlate"],
  "actor_binding": "subject-or-client-key-thumbprint",
  "continuation_nonce": "rotating-nonce"
}
```

### 6.3 Server-Side Ledger

| Field | Purpose |
|-------|---------|
| `handle_id_hash` | Lookup key |
| `issuer_organ` | Who minted |
| `audience_organ` | Who can consume |
| `authenticated_principal` | Actor identity |
| `capability_scope` | What's allowed |
| `expiry` | TTL |
| `replay_policy` | Single-use / multi-use |
| `request_state_hash` | Integrity |
| `approval_state` | 888 gate status |
| `revocation_state` | Can be revoked |
| `correlation_trace_id` | OTel linkage |

### 6.4 What NOT to Embed

- Raw credentials
- Filesystem paths
- Internal URLs
- SQL fragments
- User PII
- High-authority capability material

## 7. Filesystem Scope Replacement

Roots deprecated. Compensating boundary outside MCP semantics:

- Per-organ filesystem namespace or container mount policy
- Default deny; explicit read/write grants per tool invocation
- Canonicalize paths before authorization; block traversal + symlink escapes
- Capability-scoped resource URIs instead of arbitrary file paths
- Separate **read**, **write**, **execute**, **egress** grants
- Bind grants to: actor, workflow handle, organ, TTL, path prefix
- 888 approval for write/delete/deploy credentials; not for read-only analysis
